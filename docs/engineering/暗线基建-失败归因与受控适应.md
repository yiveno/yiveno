## 1. 失败环节归因

### 1.1 目的

把手写 taxonomy（采样卡里的 `rank_wrong` 等）收成**稳定阶段枚举**，便于暗线笔记与日后报表对齐；**不**自动判定根因。

### 1.2 阶段（`RecallFailureStage`）

| stage               | 含义                    | 典型 detailCode                                  |
| ------------------- | ----------------------- | ------------------------------------------------ |
| `not_captured`      | 目标未进库              | `no_signal`                                      |
| `index_gap`         | 索引/向量缺口           | `weak_index`                                     |
| `candidate_miss`    | 库有但未进候选/邻域     | `miss_neighborhood`                              |
| `understand_skew`   | 理解/解析偏离           | `parse_fail` · `gist_mismatch` · `missing_topic` |
| `rank_wrong`        | 进了邻域但排错/噪声顶栏 | `rank_wrong` · `hybrid_drift`                    |
| `clue_insufficient` | 用户线索不足以区分      | `clue_thin` · hedging                            |
| `absent_honest`     | 诚实无相关终局          | `absent` / `no_match` 终局                       |
| `ux_friction`       | 体验摩擦导致放弃        | `ux_friction` · `user_gave_up`                   |
| `unknown`           | 证据不足                | —                                                |

代码：`frontend/src/core/recall/dual-thread/recall-failure-attribution.ts`

### 1.3 使用方式（本阶段）

1. 研究/采样卡填写 `stage` + 可选 `detailCodes[]` + `confidence`。
2. 暗线笔记汇总只计**计数**，不写私人 clue。
3. 运行时**不**自动写入用户路径（避免脏标签）；DEV 可从遥测草图看 outcome 分布。

### 1.4 已知目标漏召检测（`assessKnownGoldRecallGap`）

在**金标 id 已知**时，用纯函数区分：

| 条件                               | 建议 stage                         |
| ---------------------------------- | ---------------------------------- |
| 不在库                             | `not_captured`                     |
| 在库、有候选列表且不在候选         | `candidate_miss`                   |
| 在库、不在邻域（候选未知或在候选） | `candidate_miss`（摘要区分）       |
| 在邻域但首屏外                     | `rank_wrong`                       |
| 已在首屏                           | `unknown`（非召回漏；查 ECS/认错） |

```ts
import { assessKnownGoldRecallGap, attributionDraftFromGoldGap } from '@/core/recall/dual-thread'

const gap = assessKnownGoldRecallGap({
  goldId,
  goldInLibrary: true,
  candidateIds, // 可选；未知则省略
  neighborhoodIds, // 本轮结果 id
  firstScreenSize: 5
})
const draft = attributionDraftFromGoldGap(gap)
```

DEV：`yiveno.assessKnownGoldRecallGap(input)`（仅开发构建）。

**未做：** 生产路径自动挂 gold、自动写 storage。

## 2. 受控适应框架（骨架）

### 2.1 原则

- 登记**可调旋钮**（param / strategy）与代码锚点、回退说明。
- **禁止**本骨架自动改值；改值 = 明线任务 + must/§5 + 可选暗线笔记。
- 评估门：合入前对照 `recall-eval` must / 金标；见双线程四边界。

### 2.2 版本

`RECALL_ADAPTATION_CONFIG_VERSION`（semver-ish 日期串）随旋钮登记表变更而 bump。  
代码：`recall-adaptation-config.ts`

### 2.3 回退

每个旋钮 `rollbackHint`：指回常量文件 / git 路径；无在线一键回滚实现（本阶段文档级）。

## 3. 暗线观测（匿名汇总）

### 3.1 汇总形状

`DualThreadAggregateSketch`：失败 stage 计数、telemetry outcome 计数、`pipelineTiming` 分位数草图；**禁止**含 clue 原文 / memoryItemId / URL。

### 3.2 DEV 导出口

`yiveno.exportDualThreadAggregateSketch()`（仅 DEV）  
从本机 TTE 缓冲生成草图 → 可粘贴进研究笔记「数据来源」节。

## 4. 研究笔记 ↔ 产品门禁

| 机制                | 作用                                     |
| ------------------- | ---------------------------------------- |
| Task Brief 五问     | 方案/新能力必填                          |
| PR 模板「双线程」节 | 人工勾选                                 |
| `bun run doc:check` | 校验权威文件 + dual-thread core 路径存在 |
| 暗线笔记模板        | 假设/替代解释/置信度                     |

**不做：** 根据 git diff 自动拦 PR（过脆）；私人会话卡入仓检查（靠纪律 + README）。
