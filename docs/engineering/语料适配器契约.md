## 1. 目标形态

```text
语料适配器
  认证（Auth）→ 拉取（Fetch）→ 映射（Map）→ 质量门禁（Gate）
  → MemoryItem（id + 出处 + 可问字段）
  → 同一理解层 / Zod 门禁 / 确定性 Filter·Hybrid
```

**Yiveno = 那个找东西的。** 适配器只负责把「用户授权的私有痕迹」变成可找回对象；  
禁止借接入做成同步中台、笔记编辑器或助理人格档案。

---

## 2. 边界（谁做什么）

| 面         | 适配器做                                           | 适配器不做                          |
| ---------- | -------------------------------------------------- | ----------------------------------- |
| **Auth**   | 用户显式授权；可撤销；token 不进 Memory payload    | 静默全盘镜像；把凭证写进 clues      |
| **Fetch**  | 增量/全量拉取；尊重用户勾选范围                    | 默认读浏览历史 / 剪贴板 / 未授权盘  |
| **Map**    | → 现有（或先扩 schema 再接线的）`MemoryItem`       | 发明并行对象模型绕过 IndexedDB      |
| **Gate**   | 拒写或降权弱锚点；写清拒绝原因（可观测）           | 空壳标题假装可找回                  |
| **Write**  | 只经 application / repository / `indexedDBManager` | LLM 直写；UI 直连 IDB               |
| **Recall** | 入库后走同一检索主链                               | 源内搜索冒充 Recall；无 id 编造答案 |

**入口溯源 vs 语料源：**

- `clues.captureEntry`：捕获**入口**（`popup` 为遗留枚举 id，原 Action Popup 时代；另有 `context_menu` / `selection_toolbar` / …），不是第三方系统 id。
- 未来外部源须另有稳定 **`corpusSource` + `remoteId`（或等价）** 才能幂等 upsert；今日书签用 `payload.chromeBookmarkId`。

## 3. 参考实现（今日两条）

| 适配器   | `type`         | Auth / Fetch                            | Map 要点                                                   | Gate（已有）                   | 已知缺口                                                                |
| -------- | -------------- | --------------------------------------- | ---------------------------------------------------------- | ------------------------------ | ----------------------------------------------------------------------- |
| **摘录** | `text_excerpt` | 当前页选区；http(s)                     | `selectedText`→`textExcerpt`；URL/页名/domain；可选 `note` | 非空选区；可保存 URL           | 上下文不进 clues（可接受）                                              |
| **书签** | `bookmark`     | Chrome bookmarks 权限；bulk + 增量 sync | title/url/domain；`chromeBookmarkId`；upsert 保留 `note`   | 非空 title/url；过滤非 http(s) | 空壳标题可入库；bulk **不经** service → 常缺 LLM enrichment / embedding |

关键路径（实现锚点）：

- 摘录：`CAPTURE_TEXT_EXCERPT` → `memoryItemService.captureTextExcerpt` → `createTextExcerptMemoryItem`
- 书签：`import-chrome-bookmarks-service` / `chrome-bookmark-sync-service` → `createBookmarkMemoryItem` / upsert

## 4. 与统一契约的差距清单（R2）

| ID  | 差距                                                               | 严重度     | 处置                                                                                                                       |
| --- | ------------------------------------------------------------------ | ---------- | -------------------------------------------------------------------------------------------------------------------------- |
| G1  | 无 `CorpusAdapter` 注册/接口；新源只能改 `type` 或硬塞现有 payload | 中         | **契约先定**；有第三方试点时再抽象接口                                                                                     |
| G2  | 无通用 `corpusSource` + `remoteId` 字段；Notion/Docs 难幂等        | 中         | 接外部源前扩 schema（先改产品文档 §2）                                                                                     |
| G3  | 无统一「弱锚点」质量门禁模块；书签仅标题+URL 即可进召回池          | 高（体验） | **R3 切片已落地**：`corpus-quality-gate.ts` 评估 + 召回降权；空壳标题不再当高权 title 字段。写库拒写 / UI 引导补 note 仍待 |
| G4  | bulk 书签旁路 `memoryItemService` → enrichment/embedding 不齐      | 中         | backlog：导入后异步补齐或接受「关键词先可用」并文档化                                                                      |
| G5  | `captureEntry: import` 枚举存在但导入实际打 `sync`                 | 低         | 可归一或修正打点；非阻塞                                                                                                   |
| G6  | 无第三方 OAuth / fetch 抽象                                        | 低（当前） | 等首个外部源再做；禁止提前平台化                                                                                           |
| G7  | 无「接入前 vs 后」口语找回对比钩子                                 | 中         | R3 试点时绑 `recall-eval` / §5 手工对比                                                                                    |

## 5. 第三方源准入 checklist（实现侧）

接代码前须全部勾选（产品「提高找回成功率」的工程展开）：

1. **命题：** 有 before/after 口语找回对比计划（must 或 §5）；预期命中率显著提升，否则不做。
2. **对象：** 每条稳定 id、可解释出处、至少一段可问正文（≈ `textExcerpt` / 用户 `note`）。
3. **门禁：** 正文/信息密度下限；不达标拒写或标弱锚点；不得默认当 Top Pick 燃料。
4. **映射：** 只产出 `MemoryItem`；写库走 service/repository；LLM 仅 enrichment 提议。
5. **主链：** 入库后同一 Filter/Hybrid/理解层；禁止并行「源内搜」。
6. **Auth：** 显式授权、可撤销；token 不进 payload。
7. **幂等：** `corpusSource + remoteId`（或已有等价）upsert；保留用户 `note` / 行为字段。
8. **边界：** 导入 ≠ 做 Notion；无编辑器/知识空间主路径。
9. **观测：** flow log（开始 / Gate 拒绝原因 / 成功 id）；可按源过滤。
10. **验收资产：** 至少一组 must 或 §5 步骤入库。

代码常量：`THIRD_PARTY_CORPUS_ADMISSION_CHECKS`（`corpus-adapter-contract.ts`）。
