# Recall · Placeholder × 追问芯片（双通道）

> **状态：** 方案已确认（2026-08-26）并合入产品文档 **§7.0 Composer 双通道**。  
> **术语：** [`Yiveno-术语表.md`](../product/Yiveno-术语表.md)（clue · 邻域 · 芯片）。  
> **实现：** P0a–P0c 已接线；**P1 切割力调参已落地**；**LLM 仅润色已选定举例已接线**（失败回退原词）。  
> **范围：** Side Panel composer 的 placeholder 与会话内追问芯片；不含 Omnibox。

## 0. 已拍板共识（摘要）

| 项                | 决定                                                                                                   |
| ----------------- | ------------------------------------------------------------------------------------------------------ |
| 目标              | 同一目标：帮下一轮在**本轮邻域内**收窄；非闲聊、非神谕指路                                             |
| Placeholder       | **软引导**；composer **对话承载体**；常驻有文案；带举例的收窄句须 grounded；**有会话标题时须点名标题** |
| 芯片              | **硬输入**（点击即发）；仅「明确需要用户确认」的槽 / 弱环境可选；点击**不**走软岔路口                  |
| 冲突优先级        | **有白名单芯片 → 以芯片为主**；placeholder 退中性短句、不带第二套举例                                  |
| 宽邻域 `top_pick` | **默认只走动态 placeholder**，不上内容芯片                                                             |
| 芯片白名单        | ① `need_a_clue` + LLM（挂候选）；② §7.1 环境芯片（弱、可选）                                           |
| 废除              | dismiss 后 `buildRecallSuggestions()` 固定银行（site/quote/note/article）                              |
| value 两轨        | 槽位/环境 = 闭集 canonical；内容举例 = **本轮结果字面 token**（禁止发明主题）                          |
| 环境芯片 P0       | **保留但弱**；与 LLM 芯片同时存在时 **不抢主**（环境芯片可隐或降级）                                   |
| 语言              | 产品面 **仅美式英语**                                                                                  |

**刻意不声称：** Yiveno「已知用户要哪一条」。掌控的是**当前邻域结构**（可切割维度），不是真值答案。

## 1. 目标 / 非目标

### 1.1 目标

1. 用户在宽邻域或弱命中后，**知道下一刀可以补什么**，且例子来自库内真实信号。
2. 减少无方向续打导致的**锚点漂移**。
3. 用软引导收获**高信噪内容词**；用硬芯片完成**缺了就难继续的确认**。
4. 与「禁止灰名单冒充通解」一致：不写死专名/主题 seed。

### 1.2 非目标（P0）

- 开放主题摘要（「这批是关于明星的」）无 grounding 生成器。
- 无候选时的缺槽问卷 / dismiss 固定芯片银行。
- Placeholder 替代结果列表或气泡状态句。
- Omnibox / Settings 文案动态化。

## 2. 双通道优先级表（Normative 候选）

| 场景                                | 气泡（assistant text）                            | Placeholder                                       | 芯片                                                 |
| ----------------------------------- | ------------------------------------------------- | ------------------------------------------------- | ---------------------------------------------------- |
| 空闲 / 新会话                       | 问候（若有）                                      | **Idle 模板**（可保留一条高质量 e.g. 或中性邀请） | 无                                                   |
| `top_pick` 且邻域偏宽（见 §4 触发） | 报 N · showing 区间；**不**列收窄举例             | **收窄型**（grounded 举例）                       | 无（默认）                                           |
| `top_pick` 且已很窄 / 已展完全池    | 报 N / all                                        | **中性续打**或 Idle                               | 无                                                   |
| `need_a_clue` + LLM 成功且带芯片    | LLM 状态/追问句；**不**重复列与芯片相同的举例清单 | **中性短句**（让位）                              | **主**：LLM suggestions                              |
| `need_a_clue` + LLM 失败 / 无芯片   | 静态不够确定 + 列表                               | 若可抽 grounded 信号 → 收窄型；否则中性           | 无规则芯片银行                                       |
| `no_match`                          | 诚实终局                                          | 中性 / Capture 向（不假装还能搜救）               | **无**                                               |
| Dismiss 后                          | 「换个角度」类文案                                | 中性续打                                          | **无**固定银行                                       |
| §7.1 环境信号可用且无 LLM 芯片      | 视 outcome                                        | 可中性或收窄                                      | **可选弱芯片**；若稍后出现 LLM 芯片 → 环境芯片不抢主 |

**硬规则：**

1. **同一时刻最多一套「带例子的收窄邀请」**——在芯片或 placeholder 二选一（芯片优先）。
2. Placeholder **始终有字符串**（常驻槽位）；「智能收窄句」仅在有货时启用。
3. 气泡负责 **结果状态**；不与 placeholder 抢「下一条件举例」。

## 3. 信号来源（grounded）

抽取对象：**本轮召回写入会话的候选集合**（优先 `candidateCards` 对应条目；宽邻域用整池语义上等于 `totalRankedCount` 背后的互异组，实现上以当前 turn 已持有的卡片/matches 为准；Show more **不改变**已抽信号的来源集合——信号按**整池**算，避免「只看到 5 条就换提示」抖动；若整池未全量持有于 UI，以 handler 返回的排序池快照为准）。

### 3.1 P0 允许信号（按切割力排序）

| 优先级 | 信号                | 来源                                   | 说明                                                               |
| ------ | ------------------- | -------------------------------------- | ------------------------------------------------------------------ |
| A      | **对象类型**分布    | `tags` / item 类型 / 编排 objectType   | 闭集；仅当存在 **≥2 种**且没有单一类型占比过高时举例               |
| B      | **高频字面 token**  | title / excerpt / note / url path 分词 | 须在 ≥2 条候选出现或信息增益高；过滤停用词与已在用户线索里出现的词 |
| C      | **注册域名 / host** | bookmark / source domain               | 存在 **≥2 个不同 host** 时才举例                                   |

### 3.2 禁止

- 已拆除的主题/实体 seed、开放「明星」类标签。
- 候选中未出现的词面。
- 把整句中文/非 en 当产品 placeholder（产品面仅 en）。

### 3.3 切割力启发式（实现指引 · P1）

- 单一类型占比 ≥ **~80%** → **不要**用该类型当举例。
- 用户线索已含的 token → 不重复举。
- 最多举 **2～3** 个例子。
- 抽不出合格例子 → **降级中性 placeholder**，禁止硬凑。
- **Token：** `df≥2`；候选 ≥3 时优先**部分覆盖**（能切开邻域）；有多 host 时丢掉全覆盖弱词。
- **Host：** ≥2 个不同 host；优先更稀有的 host 标签。
- **过滤：** DNS 结构词 + 页壳弱词（guide/docs/…）闭集；忽略 `chrome-extension` / 扩展 id host；类型 canonical（如 video）允许作类型举例。

### 3.4 LLM 润色已选定举例（可选增强 · 已接线）

**时机：** 宽邻域且 **无** 白名单芯片（否则 placeholder 让位，不浪费配额）。  
**流程：** `extractComposerNarrowExamples` →（有 clue completer）`completeComposerNarrowExamplePolishWithLlm` → `gatePolishedComposerNarrowExamples`。  
**允许：** 仅改展示形态（大小写、语料中已出现的空格/连字符）。  
**禁止：** 造词、换同义词、加额外 token。  
**门禁：** `fold(polished) === fold(selected)`（去分隔符小写）；展示串须仅大小写变体 **或** 为候选语料子串；长度不一致整表回退。  
**失败：** 静默用选定原词；结果挂 `RecallResult.composerNarrowExamples`（与 hosted/clue 同配额桶）。

## 4. 触发门槛（收窄型 placeholder）

同时满足才启用收窄型（否则中性/Idle）：

1. Outcome ∈ {`top_pick`, `need_a_clue`} 且本轮有可展示候选。
2. `totalRankedCount`（或候选互异组数）**≥ 6**（略高于首屏 5，表示「还有邻域外的同池项或列表偏宽」；可调）。
3. §3 能抽出 ≥1 个合格举例。
4. **当前 turn 没有白名单芯片在展示**（有则走中性让位）。
5. 非 `no_match` / 非纯 dismiss 恢复轮。

## 5. 文案模板（美式英语 · 草案）

实现用 i18n key；举例位由运行时填入 **已校验英文字面**。

| 键角色                                | 文案方向                            | 例                                                                                          |
| ------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------- |
| Idle                                  | 一条高质量口语 e.g. **或** 中性邀请 | 可保留现 `popup_clue_placeholder` 作 Idle                                                   |
| Narrow                                | 邀请补一个来自结果的细节            | `Still a bit broad — try something like “{a}” or “{b}”.`                                    |
| Neutral (chips present)               | 短、无举例                          | `Or add another detail…`                                                                    |
| Neutral (narrow fail / after dismiss) | 不装懂                              | `Still a bit broad — add another detail you remember…`（generic）                           |
| Miss                                  | 不暗示检索还可救                    | 保持与 miss 气泡一致的克制；或 `Save a trace if you want to find it later.`（空库场景另案） |

**Show more 文案**（已上线，非本方案核心）：`Show 5 more` / `Show all K` — 与 placeholder 通道独立。

## 6. 芯片规范

### 6.1 白名单

| 来源                                | 何时                      | value                    | 与 placeholder                                                                                          |
| ----------------------------------- | ------------------------- | ------------------------ | ------------------------------------------------------------------------------------------------------- |
| LLM `assistantFollowUp.suggestions` | 仅 `need_a_clue` + 过门   | 稳定英文；须服务候选收窄 | Placeholder → Neutral                                                                                   |
| §7.1 环境（刚存 / 刚打开 / 当前站） | 弱上下文可选；**P0 保留** | 闭集短语 / host          | 若与 LLM 芯片同屏 → **环境芯片不展示或降为次要且不改变「芯片优先」下的 Neutral 规则**（视为已有硬芯片） |

### 6.2 废除 / 债务

| 项                                                    | 处置                           |
| ----------------------------------------------------- | ------------------------------ |
| `buildRecallSuggestions()`（site/quote/note/article） | **删除调用**；dismiss 后无芯片 |
| 文档与实现不一致的「失败仍发规则芯片银行」            | 保持：**失败无规则银行**       |
| 静态唯一 placeholder                                  | 由本方案状态机替换             |

### 6.3 value 两轨（禁止混用生成器）

- **轨 A（芯片硬确认）：** 时间/行为/环境闭集。
- **轨 B（内容收窄）：** P0 **优先只进 placeholder 举例**；若未来内容也上芯片，必须共用 §3 grounded 抽取，不得另写主题词典。

## 7. 会话与状态

| 事件                           | 行为                                                    |
| ------------------------------ | ------------------------------------------------------- |
| 新一轮 recall 返回             | 按 §2 重算 placeholder 模式与芯片                       |
| Show more / Show all           | **不强制重抽**举例（整池已定）；仅更新气泡 showing 区间 |
| 用户发送（含点芯片）           | 清空输入；下一轮结果驱动新 placeholder                  |
| 用户采纳提示中的词（打进线索） | 下一轮自然变窄；不在当轮「标记已采纳」也可接受（P0）    |
| New find / 清会话              | 回 Idle                                                 |

**实现建议：** `computeComposerPlaceholder({ outcome, rankedTotal, candidates, chipsPresent, clueTokens })` 纯函数（core 或 pages 旁可测模块）+ Side Panel 注入 `RecallComposer`。

## 10. 验收（最小）

1. **Grounding：** Narrow 句中每个举例 ∈ 本轮候选字段（忽略大小写）。
2. **让位：** `need_a_clue` 且存在芯片 → placeholder ∈ Neutral 集合，无 “like …” 举例。
3. **Dismiss：** 无 site/quote/note/type 芯片。
4. **宽邻域：** `totalRankedCount≥6` 且可切割 → 出现 Narrow；人为制造单一类型全库 → 不出现无效类型举例。
5. **产品语言：** 无中文 placeholder。

## 11. 开放调参（非阻塞）

- `totalRankedCount ≥ 6`：P1 仍保留（MCP `javascript` 宽邻域有效）；可按库再调。
- 类型占比门槛：**0.8**（P1）。
- Idle 是否保留长 e.g. 句：可 A/B；与 Narrow 不要共用同一 key。
- **LLM 润色已选定举例：** 已接线；无 completer / 失败 / 有芯片 → 不润色或跳过。
