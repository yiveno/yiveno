# 全局图表语义一致性审计（2026-10-31）

> **本轮约束：** 只审计、写报告；**不**改 Mermaid / Registry / 业务代码 / 测试 / ADR / Normative / 同步脚本；**不**新增图。  
> **口径：** 代码证据与 Normative 分列；冲突单独记录；推断标 **待验证**；不得用规范冒充实现、不得用代码抹掉未废止规范。

## 0. 一句话结论

现行 **15** 张登记图已覆盖主链切片（Turnstile → Auth mint、划词 Capture / 书签灌库、Side Panel / Omnibox Recall、Open / Dismiss / Outcome、Pro 云同步），**跨域边界大体正确**（Capture≠Bookmark、Panel≠Omnibox、open≠settled、登录≠上云、书签不上云）。结构门禁绿。  
主要风险不在「大流程画反」，而在：**「sync」一词跨图多义**、**书签 full repair 的 force 注释与 Normative/图注不一致**、**全景图未互指新图**、以及 **登录迁移 / Billing / GS 仍无图**（覆盖缺口，非已有图互斥）。

## 8. 值得保留的设计决策

1. **planned 与 implemented 分锚点**（china）— 防「画出来就算上线」。
2. **边界 Note + 分图**（Capture/Bookmark、Panel/Omnibox、Open/Dismiss/Outcome）— 比一张巨图更抗漂移。
3. **算法级折叠**（Hybrid RRF、Topic embed）— 时序图不承担 ADR 正文职责。
4. **Auth 与 Turnstile 切片切开** — e2e 末端折叠 + Auth 专图，符合跨进程复杂度。
5. **Sync 宿主放 ADR-017** — 决策与门禁同文，避免运行时文膨胀。
6. **registry `notes` 写禁止项** — Brief/`docs:sync-diagrams` 的有效护栏。
7. **结构门禁与语义审计分离** — `docs:check-diagrams` 绿 ≠ 语义正确；本阶段专门补后者。
