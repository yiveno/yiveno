# 图表变更感知机制（2026-10-31）

> **本轮交付：** 现状分析 + 最小可用机制 + 脚本落地 + 五项验证。  
> **不做：** 自动改 Mermaid、语义判定、改 `docs:check-diagrams`、外网/MCP、假「间接依赖」确定性边。

---

## 0. 一句话结论

新增 `bun run docs:diagram-impact`：用 Git `--base`（或 `--paths`）对照 registry 的 `codePaths` / `doc` / `docPaths`，输出建议复核的图 id 与命中原因。命中只表示**映射触发复核**；未命中**不**断言无影响。结构门禁仍只由 `docs:check-diagrams` 负责。

## 1. 现状分析

### 1.1 Registry `codePaths` 是否够映射

| 事实                                                                                          | 含义                                       |
| --------------------------------------------------------------------------------------------- | ------------------------------------------ |
| 15 图均有 `codePaths`；多数为具体文件，部分为目录（如 `pages/sidepanel`）                     | **足以做前缀/等值直接命中**                |
| 14 条路径被多图共享（如 `turnstile.ts`×5、`memory-handler.ts`×4、`memory-item-service.ts`×3） | 一文件→多图是常态；输出须列全 id           |
| `doc` / `docPaths` 已登记                                                                     | 宿主/Normative 变更可与代码变更同样映射    |
| **无** import 闭包 / 调用图                                                                   | **不能**仅凭 registry 做确定性「间接依赖」 |

### 1.2 现有 sync 脚本可复用能力

| 已有                                             | 缺口                                           |
| ------------------------------------------------ | ---------------------------------------------- |
| `loadRegistry` / `pathExists` / mtime stale hint | 无 Git diff                                    |
| Brief 生成给 Agent                               | Brief 按 id 全量或单图，**不**按本次 diff 过滤 |
| `docs:check-diagrams` = 结构门禁                 | **不应**混入「变更感知」失败语义               |

→ **最小改动：** 共享库增加路径匹配工具；**新独立脚本**做 impact；check 不动。

### 1.3 Git diff 可靠性

| 能力         | 做法                                                              |
| ------------ | ----------------------------------------------------------------- |
| 已跟踪增改删 | `git -c core.quotepath=false diff --name-status <base>`           |
| 重命名       | `R*` → 旧路径 `D` + 新路径 `A`                                    |
| 未跟踪       | `git ls-files --others --exclude-standard` → `A`                  |
| 中文路径     | **必须**关 `quotepath`（本轮验证：默认会变成 `"…/350/…"` 假路径） |

### 1.4 一文件多图

脚本对每张候选图独立 `matchDiagramPaths`；共享路径命中多 id 时全部列出（验证 V3）。

### 1.5 间接依赖 · 现有证据边界

| 可识别（直接）          | 不可伪装成确定                |
| ----------------------- | ----------------------------- |
| codePaths 文件/目录前缀 | A import B 且仅 A 在 registry |
| doc / docPaths          | 测试夹具、生成物、未登记旁路  |
| tooling meta 路径清单   | 「同包邻近文件」启发式        |

### 1.6 漏报 / 误报

| 类型         | 例子                                                                         |
| ------------ | ---------------------------------------------------------------------------- |
| **漏报**     | 改未列入的共享 util；行为变了但 codePaths 未更新                             |
| **误报**     | 目录级 `application/memory` 下任意文件命中 dismiss 图（registry 故意挂目录） |
| **doc 连带** | 改运行时宿主 MD → 该宿主上**所有**图 doc 命中（预期：建议扫相关图）          |

## 2. 机制设计

```text
输入: --base <ref> 工作区 diff（+未跟踪）
   或 --paths [A|M|D:]path…
     ↓
规范化路径 + status
     ↓
对照 registry（可选 --id 过滤）
     ↓
分类:
  code  — 命中 codePaths
  doc   — 命中 doc / docPaths
  meta  — registry/脚本/规范等 tooling
  unmatched — 其余（仅全量模式枚举）
     ↓
输出: Markdown（默认）| --json | --write-brief → .cache/
```

**显式声明（Brief 纪律）：**

- 命中 ≠ 语义过时
- 未命中 ≠ 无影响
- **不**输出确定性「间接依赖」边

## 5. 使用说明（维护者 / Agent）

```bash
# 相对上次提交的工作区
bun run docs:diagram-impact --base HEAD

# 相对主分支（合并前）
bun run docs:diagram-impact --base origin/main --write-brief

# 单图
bun run docs:diagram-impact --base HEAD --id sync.excerpt-cloud-pro-gate

# 机器可读
bun run docs:diagram-impact --paths M:extension/src/.../omnibox.ts --json
```

Agent：读 Impact Brief → 只复核命中 id → 有语义差再改图 → `docs:check-diagrams` → 重大变更写 reports。
