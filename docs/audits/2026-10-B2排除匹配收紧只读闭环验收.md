## 2. Keyword / Hybrid / 降级 · 同一排除语义？

### 2.1 代码路径（已核对）

### 2.2 已排除文档会否回灌？

| 机制                                       | 判定                                                                           | 依据                                                       |
| ------------------------------------------ | ------------------------------------------------------------------------------ | ---------------------------------------------------------- |
| Hybrid 滤空 → `return null` → keyword 降级 | **不会**用「未排除池」交还；keyword 用同一 `parsed.excludeContentTerms` 再硬滤 | C：`hybrid-recall-backend.ts` ~1016–1026 + keyword L710    |

| 时间 soft 回退                             | soft 后再滤 exclude；**不**因排除空池单独 soft                                 | C：keyword L709–717；Hybrid L711–719                       |

## 6. B2 可否关闭

### 结论：**可以关闭 B2（匹配收紧波次）**，带条件记账

**关闭理由（充分）：**

1. 匹配收紧目标已落地且与 Normative / 单测 / 探针一致（`hike`↛`hikers`，连字符短语对齐）。
2. 生产 Keyword 与 Hybrid **源码**共用同一硬过滤；降级保留 parsed exclude；空池诚实。
3. 理解侧规则 + parse-gold must + 历史生产 NLU 已形成最小闭环；本波次明确不做 UI / L2 fuse / Phase C。

**不得解释为：**

- Hybrid fuse / merge / cache / MCP 已有调用链证明（它们多数是**代码审阅**或**模拟**）。
- L2 离线 fuse 已对齐 exclude（有意分计）。

### 剩余风险

1. Hybrid 真路径仅靠审阅——若未来 Outcome 注入池外 id，需靠 L740 二次硬滤（当前实现有，无回归测）。
2. 多轮 refine 并集无测——理论正确、回归盲区。
3. 缓存短窗旧 proposal。
4. 屈折不对称仍依赖字段侧反向（`hiking→hike`）；`-er` 人不与 `hike` 相交（有意）。

### 必要后续（关闭后可排，非关闸条件）

| 优先级             | 任务                                                                  |
| ------------------ | --------------------------------------------------------------------- |
| P1（建议，小）     | D1 Hybrid fuse exclude 单测；D2 merge exclude 单测；D3 `hiker` 矩阵行 |
| P2（可选）         | 缓存缺字段集成断言；Side Panel 意图 A MCP 一条                        |
| 明确不做（本波次） | Phase C；改 L2 fuse；改 Heard as；动 Embedding/Reranker/§5.9          |
