## 2. 缺口与误导风险

### 2.1 主缺口（对齐本轮目标）

| #   | 缺口                                     | 影响                                                             |
| --- | ---------------------------------------- | ---------------------------------------------------------------- |
| G1  | `slotAgreement` 无 `excludeContentTerms` | 否定槽不进连续分；模型「过 must 但 exclude 糊」无法用连续尺量化  |
| G2  | LLM 报告未接 `slotAgreement`             | 横向比模型只能比布尔通过率；难解释「哪类槽拖后腿」               |
| G3  | 无正/负分列                              | 单一 `meanSlotAgreement` 会把时间/类型/正词/排除混在一个平均分里 |

### 2.2 次要缺口（建议本轮**不**扩金标，仅记账）

## 3. 目标协议草案（供实施，尚未落码）

### 3.1 固定变量（与现有一致）

| 固定     | 值                                                                            |
| -------- | ----------------------------------------------------------------------------- |
| 数据集   | `PARSE_GOLD_CASES`（**不改**本轮）                                            |
| 时钟     | `PARSE_GOLD_NOW_MS`                                                           |
| 裁判语义 | 与 `diffParseGoldSlots` **同构**（同一 mustInclude/Exclude/Exact/Empty 规则） |
| 规则 CI  | 行为与 must 集不变                                                            |

### 3.2 自变量（横向比较时）

仅 NLU 实现：规则 / LLM model·compat·prompt·schema（指纹文件集已有）。

### 3.3 `excludeContentTerms` 进入 `slotAgreement`（建议）

新增字段名：`excludeContentTerms`（与 `contentTerms` 对称）。

判定（与 judge 对齐）：

| 金标声明               | 通过条件                                                   |
| ---------------------- | ---------------------------------------------------------- |
| 仅 Empty               | 实际 exclude 为空                                          |
| MustInclude（± Exact） | include 全有；Exact 则集合相等                             |
| MustExclude            | 所列不得出现                                               |
| 多键组合               | 全部满足 → 该字段 `true`（与 contentTerms 合成单布尔一致） |
| **均未声明**           | **不进分母**（`null` 省略）                                |

→ G4 half_read 在未加 Empty 前 **仍不进** exclude 连续分母（诚实）。

### 3.4 正向 vs 负向分列（建议）

| 桶           | 字段                                                                           |
| ------------ | ------------------------------------------------------------------------------ |
| **positive** | timeLabel · objectTypes · behaviorHints · noteHint · contentTerms · confidence |
| **negative** | excludeContentTerms                                                            |

报告至少输出：

```text
slotAgreement:
  overall: { mean, denominator }          # 可选保留；注明混合
  positive: { mean, denominator, perFieldHitRate? }
  negative: { mean, denominator, perFieldHitRate? }
cases[]: { slotAgreement: { agreement, fields, … } }
```

聚合口径：

- **按案**：先算该案 positive/negative 子 agreement（该桶 checkedCount=0 → NA，不进该桶宏观分母）。
- **宏观**：各案非 NA 的 agreement 算术平均（沿用 `meanSlotAgreement`）。
- **分字段命中率（推荐）**：对声明了该字段的案，`passedCount/声明数`——比单一 mean 更可解释。

### 3.5 报告版本

- 建议 `schemaVersion: 2`（或显式 `slotAgreementProtocol: 'v1'`），避免旧 Flash 快照被静默当成含 exclude 连续指标。
- 旧快照保留；新字段只出现在新跑产物。

### 3.6 明确本轮不做

| 不做                              | 原因                          |
| --------------------------------- | ----------------------------- |
| 改 `PARSE_GOLD_CASES` / must 期望 | 目标要求金标与规则 CI 稳定    |
| 改生产 Prompt / map / 规则抽取    | 评测协议优先；改 NLU 另开实验 |
| 强制 CI 跑 LLM                    | 成本与密钥；保持离线          |
| 本审计内跑 OpenAI 全量            | 可选下游；非协议落地阻塞项    |
| 用本指标宣称 §5.9 / 检索变好      | 分层纪律                      |
