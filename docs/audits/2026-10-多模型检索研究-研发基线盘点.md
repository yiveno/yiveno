**LLM vs 规则分工（FACT）：**

- **有 completer：** 默认 LLM NLU（disposition/mode 例外走规则）；失败降级规则。
- **无 completer / 离线 / eval：** 多数 runner **强制规则**。
- **规则职责：** 时间/对象/行为词典、保守否定跨度、`excludeContentTerms` 高置信表面、降级保底。
- **LLM 职责：** 口语 → 槽位提议 → Zod → map；**禁止**直接动数据平面（ADR-004/010）。

## 4. E2E · §5.9 与归因

### 4.1 验收口径（Normative）

产品文档 §5.9：

- 邻域命中 / 头名 delight / Verified Retrievals·WAU
- **TTE-V**（clue_submitted → ECS 五要素可见）P50/P90
- Success@180、ECS 合格率；Beta：TTE-V P50≤12s / Success@180≥75% / ECS≥92% 等
- 本机七事件 + `pipelineTiming` **已接线**；**无种子 study 数据前不得宣称 Beta 达标**

### 4.2 分层结果能解释什么 / 不能解释什么

| 分层信号                       | 可解释的 E2E 变化                                       | 不能归因                                |
| ------------------------------ | ------------------------------------------------------- | --------------------------------------- |
| parse-gold / LLM 槽位 regress  | 理解错导致搜偏、时间窗错、exclude 空                    | 「找得慢」（TTE）、「卡不齐」（ECS UI） |
| L2 candMiss↑                   | 库有但池无 → 邻域命中↓                                  | 排序噪声、Outcome、同域                 |
| L2 inPoolNotTop1↑              | 覆盖有、头名/首屏弱 → 头名 delight / Interaction Burden | 是否该上 Reranker（未做 L3 消融）       |
| L2 negFP↑                      | 误报进邻域 → 信任/Wrong-path                            | 若冻结槽无 exclude，**不能**反证生产 B2 |
| hybrid-eval / recall-eval 变绿 | 契约未破                                                | 真实 embedding、种子 TTE                |
| Gateway latency / tokens       | hosted NLU 健康度                                       | 检索质量、§5.9                          |

### 4.3 当前无法归因的典型问题

1. 真实库「偶发找不到」：缺自动 `assessKnownGoldRecallGap` 挂 gold。
2. TTE-V 变差：理解慢 vs 检索慢 vs 卡渲染——有 `pipelineTiming` 字段，**缺**与分层 eval 的联合报表。
3. Hybrid「感觉差不多」：L2 上 semantic≈hybrid（该样本）→ **不能**外推生产（Outcome/同域/降级/LLM 未纳入）。
4. 换 Flash / 换 Embedding 值不值：L1 缺连续+exclude 报表；L2 单 embedding；L3 无池。

## 6. 下一阶段实验设计（建议审阅）

### 6.1 最值得开展的一个实验

**名称：L2–B2 对齐复跑（冻结理解 × exclude 硬过滤）**

**不**优先换 Embedding / 不接 Reranker / 不改 §5.9 / 不进 Phase C。

### 6.2 假设

> **H1：** 在**同一** 22 题 corpus / nowMs / bge-m3 下，把意图 A 的冻结槽改为合法 `excludeContentTerms`，并在消融 Keyword/Semantic/Hybrid 路径接入与生产同函数 `filterMatchesByExcludeContentTerms` 后，`ablate-yellowstone-exclude-hike-clear` 的 **negFP 变为 false**（hiking id 不进前 K），且 hit 子集的 candMiss / R@K **不劣于**上一轮共享 20 题对照。

若 H1 成立 → L2 报告中的意图 A 误报应归因于「冻结槽/执行未对齐 B2」，而非「bge/RRF 本质无法处理否定」。  
若 H1 失败 → 再开根因（正词仍含 hike 残差、语义池在硬滤前主导、金标 lodging 缺失导致空池策略等）。

### 6.3 必须固定的变量

| 固定                           | 说明                                                  |
| ------------------------------ | ----------------------------------------------------- |
| Corpus 快照                    | `buildRetrievalAblationCorpus()` 同指纹               |
| `nowMs`                        | `RETRIEVAL_ABLATION_NOW_MS` / `RECALL_EVAL_NOW_MS`    |
| Embed 模型                     | `@cf/baai/bge-m3`（禁止 fake）                        |
| 三策略定义                     | keyword / semantic / hybrid 与现 runner 一致          |
| 既有 hit/neg 题面与 expectedId | **不**为刷指标改期望命中                              |
| 生产行为                       | **不改**；仅离线 runner + **消融用**冻结 `goldParsed` |

**唯一自变量：** B2 对齐（冻结槽含 `excludeContentTerms` + runner 硬过滤开/关对照，建议 A/B 两次跑或同跑双列）。

### 6.4 独立指标

| **禁止**                                                  | 用该次 R@K 涨幅宣称 §5.9；禁止与未对齐 B2 的旧主表混用而不标注 |

### 6.5 是否需要补金标 / 案例

### 6.7 成功 / 失败含义

| 结果                                        | 含义                                                      | 下一步                                                                                                            |
| ------------------------------------------- | --------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| **成功（H1）**                              | L2 否定误报与 B2 对齐；当前最大「检索层否定」不确定性收敛 | 可关闭「L2 否定缺口」记账；下一不确定转为 **L3 固定池**（解释 inPoolNotTop1=2）或 L1 `slotAgreement`+exclude 接线 |
| **失败**                                    | 硬过滤后仍 FP 或 hit 回归                                 | 停换模；先拆：滤前池内容、contentTerms 残差、semantic-only 路径是否漏滤                                           |
| **部分成功**（仅 keyword 好、hybrid 仍 FP） | 融合路径漏滤或滤序错误                                    | 对照生产 `fuseHybridMatches` 滤序，仍属离线对齐，非 Phase C                                                       |

### 6.8 是否值得进生产验证

| 若       | 生产验证                                                                           |
| -------- | ---------------------------------------------------------------------------------- |
| H1 成功  | **低优先**：生产 B2 已落地；只需可选 MCP/意图 A 真机一条作体验确认（非本实验必须） |
| H1 失败  | **值得**生产同构探针：确认 SW 路径 exclude 是否生效（避免「离线假失败」）          |
| 无论成败 | **不**因此改 §5.9 或宣称 Beta；**不**因此上 Reranker                               |

### 6.9 明确不选为本轮第一优先的候选项（及原因）

| 候选项                    | 为何退后                                                                  |
| ------------------------- | ------------------------------------------------------------------------- |
| 换 Embedding / 多模对照   | 当前否定与排序归因未钉死；换模无法解释旧 negFP                            |
| 接 Reranker               | 无固定池 L3 基线；L2 上 hybrid≈semantic，Reranker 收益不可证              |
| 仅跑 OpenAI N3 parse-gold | 减的是厂商选择不确定性，**不**解 L2–B2 对拍这个最大缺口；且接入方案未实施 |
| 只加单测数量              | 违反「不为刷测改定义」；不替代 real-run                                   |
