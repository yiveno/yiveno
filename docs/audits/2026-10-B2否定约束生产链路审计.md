## 3. 理解层：有无独立可执行表示？

### 3.1 Schema（C · FACT）

`ParsedRecallClueSchema`（`parse-recall-clue-types.ts`）字段闭集：

`raw` · `topic?` · `timeRange?` · `timeConfidence?` · `objectTypes?` · `behaviorHints?` · `noteHint?` · **`contentTerms`** · `confidence`

**无** `excludeContentTerms` / `mustNot` / `forbidden` / `negation` 等槽。

`LlmParsedClueProposalSchema`（`llm-parsed-clue-proposal.ts`）同样只有 `contentTerms` 等正向槽；Zod **会剥掉**未知键 → 即使模型自由写出 exclude，映射后也会丢。

### 3.2 Prompt（C · FACT）

`build-llm-parse-prompt.ts`：指示把残留词放进 `contentTerms`，并「Exclude fillers…」。  
**没有**「用户否定 / not / don't / except → 独立排除槽」的指令。  
此处的 Exclude = **提示词写法**（勿把 filler 当内容词），**不是**产品排除约束。

### 3.3 规则 parser（C + 本地执行 · FACT）

`parseRecallClue`：词典占时间/类型/行为/附注 → filler 掩码 → `extractContentTerms`。  
`RECALL_CLUE_FILLER_SURFACES` **不含** `not` / `don't` / `except`。  
对意图 A 本地跑规则：`contentTerms` 含 `…, not, day-hike, packing, checklist` —— **否定词与被排除名词全部变成正检索词**。

### 3.4 生产 LLM parse · Yellowstone A/B（A · FACT）

| 意图            | clue（摘要）                                      | LLM `contentTerms`                                | 排除槽                 | Filter 词面              |
| --------------- | ------------------------------------------------- | ------------------------------------------------- | ---------------------- | ------------------------ |
| **A** 排除 hike | …lodging…, **not** the day-hike packing checklist | `yellowstone lodging booking confirmation summer` | **无**                 | 同上（无 hike / 无 not） |
| **B** 找 hike   | Yellowstone day-hike packing checklist…           | `yellowstone day hike packing checklist`          | **无**（本意图不需要） | 正向找清单               |

模型：`deepseek-v4-flash` · HTTP 200 · generatedAt `2026-10-29T17:05:41.174Z`。

**A 的生产 LLM 行为：** 排除从句被**省略**，不是结构化排除。相对规则降级「少害」（不会用 hike 词去扫库），但仍 **无法执行**「禁止命中清单」。

### 3.5 产品文档「否定」易混（C · FACT）

`Yiveno-产品文档-v4.0.md`「行为/否定加权」、`computeDismissPenalty`、会话 `dismissedIds` 硬排除、Outcome `negativeIds` —— 均指 **结果反馈否定**，不是 clue 内 `not the X`。  
**不得**把 dismiss 能力当成线索否定约束已上线。

## 4. 传递链：转换点与丢失风险

生产主路径（C · FACT，`HybridRecallBackend.recallWithClue`）：

```
Side Panel clue
  → understandRecallClue（LLM 默认 / 规则降级）
  → mergeRecallDialogTurn → withRecallTopic
  → listForKeywordRecall(parsed)
  → excludeDismissedMemoryItems（仅会话 dismiss）
  → buildClueEmbeddingText(parsed.contentTerms…)
  → keyword + semantic → RRF fuse
  → 时间硬/软 + 佐证（keyword 硬 / hybrid 软罚）
  → Outcome pairs → collapse → 终排
```

| #   | 转换点              | 文件 / 函数                                                    | 否定约束是否可存活              | 丢失风险                    |
| --- | ------------------- | -------------------------------------------------------------- | ------------------------------- | --------------------------- |
| 1   | Prompt → LLM JSON   | `buildLlmParseClueMessages`                                    | 无指令产出排除槽                | **必丢（设计）**            |
| 2   | JSON → Zod proposal | `LlmParsedClueProposalSchema.parse`                            | 无字段；未知键丢弃              | **必丢**                    |
| 3   | proposal → Parsed   | `mapLlmProposalToParsedClue`                                   | 只映射正向槽                    | **必丢**                    |
| 4   | 规则降级            | `parseRecallClue`                                              | `not`+被否名词进 `contentTerms` | **语义反转（当正词）**      |
| 5   | Filter 词面         | `buildFilterClueFromParsed` ← `effectiveContentTermsForRecall` | 拼接全部 contentTerms           | 规则路径会把排除词当查询    |
| 6   | Embedding 句        | `buildClueEmbeddingText`                                       | 拼 contentTerms                 | 同 5；生产 LLM-A 则无排除词 |
| 7   | 时间 / 类型 / 行为  | `filterMatchesByParsedTimeRange` / score boosts                | 无关线索排除                    | N/A                         |
| 8   | 内容佐证            | `filterMatchesByContentTermCorroboration` / softPenalize…      | **要求正词佐证**，不排除负词    | 不执行排除                  |
| 9   | dismiss / Outcome   | `excludeDismissedMemoryItems` / `applyStoredOutcomePairs`      | 仅反馈负例                      | **另一类否定**              |
| 10  | 终排                | RRF + collapse                                                 | 无排除特征                      | 无法兑现「不要 X」          |

**丢失判定：** 在步骤 1–3 **结构上已无约束**；步骤 4 若触发则变成**有害正信号**。不是「传到过滤层才丢」。

### 6.3 现有测试覆盖（C · FACT）

| 测什么                                     | 有无「线索内明确否定」                                               |
| ------------------------------------------ | -------------------------------------------------------------------- |
| `parse-gold` 的 `contentTermsMustExclude`  | **无** — 只禁 filler/误槽泄漏（verse/thing/like…）                   |

**覆盖缺口：** 生产同构「理解是否抽出排除槽」+「过滤是否执行排除」两条均缺。

1. **Parse 金标（must）：** 意图 A → 期望 `excludeContentTerms` 含 hike/packing/checklist 类词，且这些词 **不**在 `contentTerms`；意图 B → 无 exclude、正词含 checklist。
2. **过滤单测：** 给定已含 `excludeContentTerms` 的 `ParsedRecallClue` + 迷你库（lodging 缺省 / hiking 在库）→ keyword/hybrid 在 Top-K **不得**出现 hiking（硬）或 score 显著低于无排除基线（软）。
3. **可选 MCP：** Side Panel 提交意图 A（真实库有 Yellowstone 清单时）观察邻域 —— **与单元测分计**；本审计未跑 UI。

## 8. 最小修复方案（**待裁定 · 未改码**）

### 8.1 建议形态（最小）

1. **Schema（闭集产品槽，须先改 Normative 再接线）：**
   - `LlmParsedClueProposal.excludeContentTerms?: string[]`
   - `ParsedRecallClue.excludeContentTerms?: string[]`
2. **Prompt：** 明示 `not / don't / except / rather than` 等范围写入 `excludeContentTerms`，**禁止**再进 `contentTerms`；与 `half_read`（not finished）消歧。
3. **map：** 确定性规范化 / 去重；与正词互斥（同词不得双挂）。
4. **执行（二选一，须产品裁定）：**
   - **Hard（推荐先小库评测）：** 候选若对任一 exclude 词有词面佐证 → 剔除（类似佐证门的反向）。
   - **Soft：** 佐证到 exclude 词则扣分（类 hybrid corroboration soft penalty）。
5. **规则降级：** 可选轻量：识别 `, not the …` / `not the …` 跨度 → 填 exclude；否则至少 **勿**把孤立 `not` 当 contentTerm（filler）。
6. **回归：** §6.4 三条；不改 §5.9 阈值；L2 金标本阶段不动。

### 8.2 潜在副作用

| 风险              | 说明                                                                                        |
| ----------------- | ------------------------------------------------------------------------------------------- |
| 过度排除          | 「not sure / I don't remember」若误进 exclude → 伤正邻域（芯片已禁元确认，parser 须同样挡） |
| 与 half_read 冲突 | `did not finish` 已是行为词典                                                               |
| Hard 空窗         | 排除过猛 → 邻域空；需与时间 soft 回退策略对齐（禁止糊排除单独硬空？待产品定）               |
| Prompt 漂移       | 只改 Prompt 不改 schema → Zod 仍丢字段，**无效**                                            |
| 多轮 merge        | `mergeRecallDialogTurn` 须定义 exclude 并集/覆盖规则                                        |

### 8.3 明确不在最小修复内

换 Embedding · Reranker · Phase C · 扩大 L2 样本 · 改 §5.9。
