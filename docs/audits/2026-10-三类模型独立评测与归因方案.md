# 三类模型独立评测与归因方案（2026-10 审计）

> **本文件 = 审计 + 协议 + 分阶计划。** Phase A 已落地；Phase B **已扩充并真实跑通**（20 题 / MRR·nDCG / candMiss 分计），详见 [`2026-10-L2召回消融实验报告.md`](./2026-10-L2召回消融实验报告.md) 与 [样本设计](./2026-10-L2召回消融-样本设计与实现差异.md)。**未**改检索算法 / 提示词 / 模型配置 / §5.9；**未**进 Phase C。  
> 标签约定：**FACT** = 仓库证据；**INFERENCE** = 由证据合理推断；**建议** = 设计意见；**待验证** = 未跑实验的假设。  
> **一句话目标：** 每次检索优化都能回答——改了什么、哪个分层指标变了、为什么变、是否值得进生产。

## 0. 结论先行

| 判断         | 内容                                                                                                                                                                                                                                                           |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **方向**     | 理解 / 召回覆盖 / 排序 **分轨评测** 与端到端 §5.9 **分计**——与产品 Normative「理解层 → 检索层」及暗线 `RecallFailureStage` 一致。                                                                                                                              |
| **现状**     | 三套 eval **已存在且可复现**，但职责混叠：`recall-eval` 把规则理解 + 关键词检索 + 排序揉成一条 pass/fail；`hybrid-eval` **不**测真实 embedding 质量（fake 向量 + 强制同向）；**无** MRR/nDCG；**无**「固定金标约束 + 固定候选池」的排序消融；**无** Reranker。 |
| **最小路径** | **不要**新建评测框架。在现有 `eval/` 上加：**固定 `ParsedRecallClue` 注入**、**策略开关（keyword / semantic / hybrid）**、**位次指标**、**与 `assessKnownGoldRecallGap` 对接**。                                                                               |
| **硬闸**     | 分层指标涨 ≠ 可进生产；须 must 不退 +（用户可感）MCP/§5 或种子 TTE 另轨。禁止用 Schema 通过率 / 降级率 / 单次总分冒充检索质量。                                                                                                                                |

### 1.3 混叠与误导风险（INFERENCE）

1. **`recall-eval` 绿 ≠ 理解准，也 ≠ Hybrid 好。** 失败时无法自动知道是 `understand_skew` 还是 `candidate_miss` / `rank_wrong`（归因枚举已有，未接线）。
2. **`hybrid-eval` 绿 ≠ embedding 模型好。** FACT：`embeddingAnchor` + `makeFakeEmbedding` 把目标钉成余弦 1；测的是融合/门禁/R0 契约。
3. **两套 corpus / 两套时钟 / 两套用例** → 不能把 recall-eval 与 hybrid-eval 的 pass 率加减当「Hybrid 增益」。
4. **parse-gold 与 recall 时钟差 3 天** → 同一相对时间标签派生的绝对窗不同；跨集拼「时间+命中」实验须统一 `nowMs`。
5. **Schema/Zod 通过率、`rules_fallback` 率**（任务路由方案 §5）是 **NLU 工程健康度**，不是邻域命中率。

## 2. 分层评测设计（建议）

对齐三类模型职责（非厂商名）：

```text
L1 理解（生成式 NLU）     clue → ParsedRecallClue（相对金标槽位）
L2 召回覆盖（关键词 / Embedding / Hybrid 池）  固定金标约束 → 候选是否含目标
L3 排序（规则分 / RRF / 可选 Reranker）       固定同一候选池 → 位次质量
E2E 端到端（产品）         §5.9 TTE / 邻域命中 / ECS；现有 must 作回归护栏
```

### 2.1 L1 · 理解层

| 项           | 约定                                                                   |
| ------------ | ---------------------------------------------------------------------- |
| **固定**     | `PARSE_GOLD_CASES`（或子集）· `nowMs` · completer/model 指纹（LLM 跑） |
| **变量**     | 仅 NLU 实现（规则 / LLM prompt·schema·型号）                           |
| **评分**     | 既有 `judgeParseGoldCase`；新增**连续**「槽位一致率」（见 §4）         |
| **禁止证明** | 找得到、Hybrid 更好、配额更省                                          |

**最小改动：** 复用 `runParseGold` / `compareParseGoldWithLlm`；加报表字段，不改生产解析。

### 2.2 L2 · 召回层（覆盖率）

| 项                           | 约定                                                                                                                                                                                |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **固定**                     | 合成 corpus 快照（优先**新建薄集**或复用 hybrid corpus id）· 金标 `ParsedRecallClue`（人工或从 parse-gold 期望物化）· `nowMs` · 池上限常量（`HYBRID_KEYWORD_POOL=100` / semantic 24 | 100） |
| **变量**                     | 单策略：`keyword_only` \| `semantic_only` \| `hybrid_rrf`（后两者生产路径已有积木：`filterKeywordMatchesBeforeCollapse` / `rankIdsByCosineToQuery` / `fuseHybridMatches`）          |
| **评分**                     | Recall@K（候选池或融合后邻域，须在报告标明**哪一层集合**）                                                                                                                          |
| **缺失目标**                 | 目标不在策略产出集合 → 记 `candidate_miss`；**不算**排序失败                                                                                                                        |
| **真实 embedding（可选轨）** | 另轨：对同一文本用 Worker `bge-m3` 出向量（需登录/配额）；与 fake 轨 **分计**，禁止混进 CI must                                                                                     |

**最小改动：** 新 runner（如 `run-retrieval-ablation.ts`）调用现有纯函数；用例显式带 `goldParsed` + `expectedId`；**不要**在 vitest 里再实现一套 RRF。

### 2.3 L3 · 排序层

| 项       | 约定                                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **固定** | 同一有序/无序**候选池**（由 L2 某次成功运行导出 id 列表 + 条目快照）· 金标 id · 展示截断 K（默认 `RECALL_RESULT_PAGE_SIZE=5`） |
| **变量** | 仅排序器：现网 `buildRecallResult`/分数序 · 纯 RRF 序 ·（未来）Reranker                                                        |
| **评分** | MRR · nDCG@K · Top-1 命中率；并列名次规则见 §3                                                                                 |
| **禁止** | 池内无目标却评排序；用换 embedding 冒充排序实验                                                                                |

**最小改动：** Phase B 先做「从现成 `RecallMatch[]` 重排打分」工具函数 + 指标；**不**先引 Reranker 模型。

### 2.4 E2E · 端到端（保留）

| 尺                             | 作用                 | 不能证明                |
| ------------------------------ | -------------------- | ----------------------- |
| `recall-eval` must             | 关键词主路径回归护栏 | Hybrid / LLM / 真实语义 |
| `hybrid-eval` must             | Hybrid **契约**回归  | embedding 型号质量      |
| §5.9 TTE-V / Success@180 / ECS | 产品验收             | 哪一层坏了              |
| MCP UI 抽测                    | 用户可感路径         | 统计显著性              |

## 3. 实验协议（建议 · 可比性）

### 3.1 每次实验必钉死

| 钉死项            | 做法                                                                                         |
| ----------------- | -------------------------------------------------------------------------------------------- |
| **数据集版本**    | 用例文件 git SHA + case id 列表；corpus builder 函数名与条目 id 集合哈希                     |
| **金标**          | L1：`expect` 槽位；L2/L3：`expectedId`（及可选相关 id 多标签，默认单相关）                   |
| **理解快照**      | L2/L3：序列化 `ParsedRecallClue`（或从金标槽位确定性物化）；**禁止**实验中再 LLM             |
| **索引/向量快照** | fake：anchor 文本 + dim；真实：model id + 条目 embedding 是否预计算、缺失策略（跳过 / 失败） |
| **时钟**          | 单实验统一 `nowMs`（建议消融集一律用 `RECALL_EVAL_NOW_MS`）                                  |
| **配置指纹**      | 池 limit、RRF k、佐证门开关、pageContextMode、outcome pairs（eval 默认 `[]`）                |
| **单变量**        | 变更清单只允许一类：NLU / 表示 / 召回策略 / 排序器 / 门禁阈值                                |

### 3.2 候选池构造

| 策略            | 构造（对齐现网积木）                                                  | 报告字段                         |
| --------------- | --------------------------------------------------------------------- | -------------------------------- |
| `keyword_only`  | 关键词打分 → 折叠 → 池 limit                                          | `candidateIds` 有序              |
| `semantic_only` | 全库已嵌入条目余弦 Top-K（过 `HYBRID_MIN_COSINE_SIMILARITY`）         | 同上                             |
| `hybrid_rrf`    | `fuseHybridMatches` 成功路径的融合序（或降级 null → 记策略失败/回退） | `neighborhoodIds` + `hybridUsed` |

**与展示邻域：** L2 主报「策略产出集合是否含目标」；若只报 UI 邻域须标注 `after_collapse` / `page_size`。

### 3.3 边界约定

| 情况           | 处理                                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **目标不在池** | L2 失败；L3 **跳过**该 case（或记 NA）；归因 `candidate_miss`                                                             |
| **并列分**     | 稳定次序：现网已有「同分按 id `localeCompare`」（见 `sortIdsByRrf`）；指标按**最终稳定序**算位次，禁止随机打散            |
| **多相关文档** | P0 单 `expectedId`；多相关留 P2（nDCG 增益）                                                                              |
| **失败样本**   | 落盘 caseId + 层 + 实际 top ids + 金标 parsed 摘要（无私人真实库 clue 进 git）                                            |
| **随机性**     | CI / fake：零随机。真实 embed / LLM：记录 model·seed（若有）·温度；同配置重复 ≥3 次报区间（待验证是否生产 API 支持 seed） |
| **真实库实验** | 另轨：维护者真实 Profile；结果进研究笔记 / 本机，**不**默认进 must；遵守「探针库 ≠ §5.9」                                 |

### 3.4 与归因枚举对接

跑完一条 L2/L3/E2E 后，调用 `assessKnownGoldRecallGap`：

| 条件                  | stage                              |
| --------------------- | ---------------------------------- |
| 不在库                | `not_captured`                     |
| 不在候选              | `candidate_miss`                   |
| 在邻域但首屏外        | `rank_wrong`                       |
| L1 槽位失败且下游未跑 | `understand_skew`（人工/脚本前置） |

**待验证：** 自动从 parse-gold 失败推断 `understand_skew` 是否过拟合（部分 stretch 故意超规则能力）。

## 4. 指标定义（建议）

### 4.1 分层指标

| 指标                          | 层             | 定义（本方案）                                                                                                                                                                                                                                                      | 能证明           | 不能证明               |
| ----------------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- | ---------------------- |
| **槽位一致率**                | L1             | **字段级**（`SLOT_AGREEMENT_PROTOCOL=field-v1`）：与 `diffParseGoldSlots` 同构；含 `excludeContentTerms`。主报 **positive** / **negative** mean + denominator + per-field hit rate；overall 仅辅助。未声明字段不进分母（NA）。**不是**词项 P/R/F1。另报 must 通过率 | NLU 相对金标字段 | 检索质量；词项级准确率 |
| **Schema/Zod 通过率**         | L1 工程        | LLM 输出可解析且过门禁                                                                                                                                                                                                                                              | 管道稳定性       | 槽位语义正确；找得到   |
| **`rules_fallback` 率**       | L1 工程        | 生产理解降级占比                                                                                                                                                                                                                                                    | 可用性/配额压力  | 检索质量               |
| **Recall@K**                  | L2             | 目标 ∈ 策略产出前 K（K 默认 5/10/24，报告写明集合）                                                                                                                                                                                                                 | 覆盖能力         | 排序是否可用；用户 TTE |
| **MRR**                       | L3             | 均值 1/rank（无目标记 0；协议规定 NA 则排除）                                                                                                                                                                                                                       | 首位附近质量     | 覆盖；理解             |
| **nDCG@K**                    | L3             | 单相关简化：目标在 r → \(1/\log_2(r+1)\)（无目标 0）                                                                                                                                                                                                                | 截断前排序       | 覆盖                   |
| **Top-1 命中率**              | L3/E2E delight | topPick.id == expectedId                                                                                                                                                                                                                                            | 头名 delight     | 邻域履约主尺           |
| **邻域命中@K**                | E2E            | 与现 `in_topk` 同                                                                                                                                                                                                                                                   | 会话履约代理     | 哪一层贡献             |
| **TTE-V / Success@180 / ECS** | E2E 产品       | §5.9                                                                                                                                                                                                                                                                | 真人真实库体验   | 模型选型细节           |

## 6. 后续决策门槛（建议）

在 **Phase B 基线可复现且样本足以区分策略**之前，默认：**不**换 embedding 型号、**不**引 Reranker、**不**为「可能更准」加多跳 NLU（ADR-010）。当前 B 已跑通但 hit 分母仅 6 → **仍适用本闸**。

| 信号（分层）                                          | 优先动作                                                    | 延迟/成本注意                               |
| ----------------------------------------------------- | ----------------------------------------------------------- | ------------------------------------------- |
| L1 槽位差、L2 在**金标约束**下覆盖已高                | 优化 NLU（prompt/schema/型号）；走任务路由 T-NLU            | 主路径墙钟；hosted 配额                     |
| L1 好、keyword Recall@K 低、semantic（**真实**轨）高  | 加强 Hybrid 触发/池；查倒排与索引缺口 `index_gap`           | embed 调用与登录门禁                        |
| L1 好、keyword 高、semantic 真实轨也低                | 查表示模型/灌库 embedding 覆盖/文本拼接 `clueEmbeddingText` | 全库重嵌成本高 → 先抽样                     |
| L2 三策略覆盖接近、L3 MRR/nDCG 差（目标在池但位次差） | 调规则分/RRF/词面保护/佐证软罚；**再**考虑 Reranker         | Reranker = 额外模型与延迟；须 Δ 质量 > 成本 |
| 仅 E2E/must 抖、分层无 Δ                              | 查用例脆、时钟、折叠、佐证门、UI——**不要**先换大模型        | —                                           |
| §5.9 真人库差、分层合成集满分                         | 合成集外推失败 → 扩真实匿名 case / 种子研究；禁止宣称 Beta  | —                                           |

**引入 Reranker 的硬门槛（建议同时满足）：**

1. L2：金标约束下目标进池率已达可接受线（待维护者定，起步可设 must 集 Recall@24 ≥ 现网 hybrid）。
2. L3：固定池上规则/RRF 的 MRR 显著低于「上界」（例如人工理想序或交叉编码试跑）。
3. 延迟：Side Panel 可感预算内（与理解 12s 门禁分计；检索段 P95 不拖垮 TTE）。
4. must + 契约 hybrid-eval 不退；内容佐证门不被绕过（产品 Normative）。

**换 Embedding 型号门槛：** 真实轨 ΔRecall@K 稳定为正 + 索引迁移成本可接受 + fake 契约 must 仍绿（防融合回归）。
