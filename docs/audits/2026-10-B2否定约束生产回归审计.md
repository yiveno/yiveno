## 1. 排除匹配语义（代码事实）

### 1.1 实现（C）

`itemHitsExcludeContentTerms` → `itemCorroboratesContentTerms` → `fieldCorroboratesTerm`  
（`content-term-corroboration.ts`）：

```text
normalize(field).includes(term)
|| compact(field).includes(term)
|| compact(field).includes(compact(term))   // compactTerm.length ≥ 2
|| latinInflectionVariants(term) 同上
|| host 变体（排除词少见）
```

**无**词边界、**无**同义词表、**无**短语对齐器。排除与正佐证**同一匹配器**。

### 1.2 LLM `hike` vs 规则 `day-hike`（B · 探针）

| 条目标题                                        | exclude=`[hike,packing,checklist]`（LLM 生效集） | exclude=`[day-hike,packing,checklist]`（规则） |
| ----------------------------------------------- | ------------------------------------------------ | ---------------------------------------------- |
| Yellowstone **day-hike** packing checklist      | 命中                                             | 命中                                           |
| Yellowstone lodging booking confirmation        | 不命中                                           | 不命中                                         |
| Yellowstone **day hike** guide                  | 命中（hike 子串 / packing 等）                   | 命中（compact `dayhike`）                      |
| Yellowstone lodging for **hikers**              | **命中（子串）**                                 | 不命中（无 packing/checklist/day-hike）        |
| **Ashike** lodging…（正文含 “without packing”） | 命中                                             | 命中（正文 **packing** 子串）                  |
| Kitchen **packing** tips                        | 命中                                             | 命中                                           |

探针：`docs/audits/snapshots/2026-10-30-B2-exclude-match-probe.json`  
单测锁定：`exclude-content-terms.test.ts`（hike↔day-hike、hikers 子串风险）。

### 1.3 推断与风险

| ID  | 内容                                                                               | 类型                |
| --- | ---------------------------------------------------------------------------------- | ------------------- |
| I1  | LLM 拆成 `hike` 比规则 `day-hike` **更宽**，覆盖 hyphen/space，也更易误杀 `hikers` | INFERENCE           |
| R1  | 子串误杀（短排除词 / 正文顺带出现 packing）                                        | **剩余风险**        |
| H1  | 若改词边界匹配，可降误杀，但可能漏 `day-hike`∋`hike` 除非保留 hyphen 特例          | HYPOTHESIS · 待裁定 |

**本批不改匹配器**（属产品行为变更）。

## 2. 硬过滤完整性（生产路径）

### 2.1 已接线（C）

| 路径                                                            | 排除执行点                                                                                      |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Keyword `applyTimeFilterThenContentCorroborationWithSoftReopen` | 正佐证后 + 时间 soft 回退后各一次                                                               |
| Hybrid `fuseHybridMatches`                                      | soft 佐证后、时间 soft 后、Outcome pairs 后再一次                                               |
| Hybrid → keyword 降级                                           | `finalizeKeywordResult` → `recallByKeywordWithParsedClue(parsed)`，**同一 `merged` 含 exclude** |

- 降级 keyword **不丢** `excludeContentTerms`。

| -------------------------------- | --------------------------------------------------------------- |

## 4. 兼容性（C）

| 面                                   | 行为                                                                    |
| ------------------------------------ | ----------------------------------------------------------------------- |
| `ParsedRecallClueSchema`             | `excludeContentTerms` **optional**                                      |
| LLM proposal Zod                     | nullable optional；缺省 → map 当 `[]`                                   |
| `llm-parse-cache`                    | 缓存 **proposal**；旧条目无字段 → 映射后无排除（TTL≤5min 同 clue 风险） |
| 多轮 `mergeParsedRecallClues`        | 并集 + 冲突消解                                                         |
| Side Panel `dialogState.accumulated` | 内存会话；关 Panel 即丢；整对象 merge，新字段随 parsed 走               |
| IndexedDB MemoryItem                 | **不**持久化 ParsedRecallClue（无关）                                   |

旧缓存短窗内可能「同 clue 仍无排除」——运维上换 Prompt 后可 `clearLlmParseCache`；**非** schema 破坏。

## 8. 明确缺陷？本批裁定

| 现象                                  | 是否「明确生产缺陷」须立刻改码 | 说明                               |
| ------------------------------------- | ------------------------------ | ---------------------------------- |
| `hike` 子串误杀 hikers                | **否（已知权衡）**             | 与佐证门同源；改边界匹配需产品裁定 |
| 正文 “without packing” 仍命中 packing | **否（已知权衡）**             | includes 语义；不引入逻辑推理      |
| L2 fuse helper 无 exclude             | **否（非生产）**               | 生产走 `fuseHybridMatches`         |
| 回声不展示 exclude                    | **体验缺口**                   | 不影响过滤正确性                   |
| 旧 LLM 缓存 5min                      | **低风险**                     | 可文档化清缓存                     |

**未自动扩大排除词、未改产品行为。**

### 若裁定要修：最小方案（仅提案）

1. **子串**：排除匹配改为「词边界或 hyphen 复合」；单测锁定 hike∤hikers 且 hike∈day-hike。
2. **回声**：Heard as 增加 `excluding: …` 芯片（i18n）。
3. **L2**：可选让 `fuseKeywordAndSemanticPools` 后接 exclude（评测对齐生产；不改金标）。
