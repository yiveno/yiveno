# Yiveno 多模型架构：第一阶段准备工作

> **本文件 = 审计 + 评测设计 + 选型标准 + 下一阶段计划。**  
> **不做：** 改生产代码 / Prompt / 环境变量 / 生产模型；不上多 Agent；不编造评测数字。  
> **验收：** 能说清有哪些 AI 任务、各自怎么量质量、怎么比候选模型、什么证据才够分模。

## 0. 结论摘要（先读）

| 问题                   | 答案                                                                                                                                                  |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 现在有多少类 AI 任务？ | **6 个 chat `taskKind`** + **1 个 Embedding（非 chat）**                                                                                              |
| 生产聊天模型？         | 全任务默认 **`deepseek-v4-flash`**（未配 `AI_HOSTED_MODEL_*` 分档时）                                                                                 |
| 工程底座？             | Phase 0–1 已落地：`taskKind` + 服务端 `maxTokens` 钳制 + 分档 env **插座**；未配分档 = 行为与今日同模                                                 |
| 主检索链路上的 LLM？   | **仅 `nlu`（clue → 槽位）**；Framing / Narrow 是旁路 NLG，**不改** Filter/Hybrid 约束                                                                 |
| `follow_up_nlg` 现状？ | completer + schema **已实现**；生产主路径芯片多由 **`framing_nlg` 同次输出**挂上；独立 `completeRecallFollowUpWithLlm` **未见 Hybrid 接线**（仅单测） |
| 够不够现在换模？       | **不够。** 缺分任务基线（延迟/失败/schema）与离线同输入对比；且路由指标 ≠ §5.9                                                                        |
| 下一阶段做什么？       | 先采两周基线（方案 §5.3）+ 搭 **NLU 离线对比**（固定 parse-gold / stretch）；无触发表命中则 **保持 Flash 单模**                                       |

| **FACT**           | 仓库代码 / 权威文档可核对  |

## 1. 调用点盘点（FACT）

### 1.1 总拓扑

```text
【主检索 · chat】
Side Panel Hybrid
  → understandRecallClue(+completer)
       → parseRecallClueWithLlm          taskKind=nlu
       → Zod LlmParsedClueProposal → ground → ParsedRecallClue
  → 确定性 Filter / Hybrid（含可选 embed）
  →（旁路）Framing NLG                   taskKind=framing_nlg
  →（旁路）Narrow 举例润色               taskKind=narrow_polish

【异步 · chat】
Capture / 冷启动队列
  → POST /api/ai/enrichment/complete     （专用路由；闭集 kind 含 enrichment）
Getting Started
  → POST /api/ai/gs-clue-samples/complete（专用路由；闭集 kind 含 gs_samples）

【向量 · 非 chat】
Hybrid / 异步写库
  → POST /api/ai/embed                   Workers AI @cf/baai/bge-m3
```

**HTTP 入口（Worker `aiRouter`）：**

| 路径                                    | 用途                              | 鉴权 / 配额（摘要）                                                       |
| --------------------------------------- | --------------------------------- | ------------------------------------------------------------------------- |
| `POST /api/ai/hosted/complete`          | Pro/登录托管 chat（NLU+NLG 主桶） | Bearer；月配额 Free **60** / Pro **2000**；日盖 Free **10** / Pro **120** |
| `POST /api/ai/clue/complete`            | 开发 / 未登录降级 chat            | IP 日配额                                                                 |
| `POST /api/ai/enrichment/complete`      | Capture enrichment 提议           | 独立 enrichment 配额路径                                                  |
| `POST /api/ai/gs-clue-samples/complete` | GS 示意 clue×4                    | IP 日配额                                                                 |
| `POST /api/ai/embed`                    | bge-m3 向量                       | Bearer；embed 日配额分档                                                  |
| `GET /api/ai/hosted/quota`              | 配额快照                          | Bearer                                                                    |

**客户端超时（FACT）：** `CLUE_LLM_COMPLETE_TIMEOUT_MS = 12_000`；Abort → 理解层 `rules_fallback`（NLU）；NLG 失败则静默回规则模板 / 跳过润色。

**服务端模型解析（FACT）：** `resolveHostedModelForTask`；未设 `AI_HOSTED_MODEL_NLU|NLG|ENRICHMENT|GS_SAMPLES` → 全局 `AI_HOSTED_MODEL` ∥ `deepseek-v4-flash`。客户端**禁止**传任意 `model` 名。

**maxTokens 钳制（FACT）：** nlu/enrichment/gs **400**；framing/follow_up **256**；narrow_polish **128**。

| --- | ------------------- | ---------------------- | ----------------------------------------------------- | ----------------------------- | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |

### 1.3 主路径调用链（代码锚点）

```text
hybrid-recall-backend
  getClueLlmCompleter()  // Omnibox / 离线可省略
  understandRecallClue(clue, { complete })     // nlu
  … Filter / Hybrid（requestWorkerEmbeddings） // embed
  completeComposerNarrowExamplePolishWithLlm   // narrow_polish（条件）
  attachRecallFraming → attachRecallFramingLlmPolish  // framing_nlg（条件）
```

**Completer 装配：** `hosted-clue-understand-api-client` / `clue-understand-api-client` → `LlmChatCompleter(messages, { taskKind })` → hosted 或 clue complete。

**ADR 边界（不变）：**

- ADR-004：LLM 只出提议；Zod/门禁 → 确定性执行；事实源 = IndexedDB。
- ADR-010：默认**单次** NLU；NLG 旁路不得改写检索约束；Stage 2 仅门禁触发（**代码侧未见默认 Stage 2 生产路径**）。

### 1.4 频率与成本结构（定性 · HYPOTHESIS 待日志证实）

| 调用                        | 相对频率                     | 对用户墙钟                              |
| --------------------------- | ---------------------------- | --------------------------------------- |
| `nlu`                       | 最高（几乎每次完整找）       | **关键路径**（计入可见进展 / TTE 等待） |
| `framing_nlg`               | 中（条件触发）               | 结果后；失败不可感检索错                |
| `narrow_polish`             | 低于 framing                 | 低                                      |
| `follow_up_nlg`             | 近 0（未接线）               | —                                       |
| `enrichment` / `gs_samples` | 与 Capture / onboarding 绑定 | 异步，不挡单次找                        |
| `embed`                     | Hybrid 常伴随；异步补向量    | 失败可降级关键词                        |

**禁止：** 用 hosted 调用次数或 token 冒充「找得准」。

## 2. 任务质量标准

### 2.1 三层尺子（必须分清）

| 层                         | 量什么                                             | 成功                     | 失败                                      | 可否单独驱动换模                                  |
| -------------------------- | -------------------------------------------------- | ------------------------ | ----------------------------------------- | ------------------------------------------------- |
| **L1 Schema 合法率**       | 原始补全 → Zod / 解析器                            | 解析通过且门禁可映射     | JSON 烂、缺字段、超界 enum                | 弱信号：可换模或改 prompt；**不够**证明找东西变好 |
| **L2 任务正确率**          | 相对任务金标（槽位 / 文案门禁 / enrichment merge） | 与 expect 一致（见下）   | 合法但槽位错、芯片无切割力、造词不过 fold | **NLU 的主离线尺子**                              |
| **L3 最终检索 / 体验质量** | 邻域含目标、must、TTE/ECS、Outcome                 | 短名单含 gold；§5.9 另轨 | 空邻域 / 弱 embedding 甩无关 / TTE 差     | **产品北极星**；路由成功 ≠ L3 成功                |

```text
L1 高 + L2 低  → 模型「会填表」但「听不懂」
L2 高 + L3 低  → 理解对了，Filter/Hybrid/索引/库内容问题（勿怪模型）
L3 好 + L1 偶发失败 → 降级规则仍可用；优先稳 schema，勿神化换模
```

### 2.2 分任务：成功 / 失败定义

#### A. `nlu`（优先 · 核心线索理解）

| 维度             | 成功                                                                                                                                      | 失败                                                                                       |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 运行时           | `source=llm`，Zod 过，下游 proceed                                                                                                        | 超时 / provider_error / Zod 失败 → `rules_fallback`；或 `rejected_noise`（网关，非模型锅） |
| L2（parse-gold） | `judgeParseGoldCase` 无 failures：约定槽位（timeLabel / objectTypes / behaviorHints / noteHint / contentTerms 包含或 exact / confidence） | 任一 expect 槽位不符                                                                       |
| 与 L3 关系       | NLU 正确是 L3 **必要条件之一**，非充分条件                                                                                                | 禁止用「Zod 通过率↑」宣称 §5.9 达标                                                        |

**现有资产（FACT）：** `PARSE_GOLD_CASES` ≈ **29 must + 8 stretch**；`run-parse-gold` / `compare-parse-gold`（规则 vs LLM）。must 挡规则回归；stretch 供 LLM 对比抬升。

#### B. 目标内容找回（L3 · 与模型选型分计）

| 尺子               | 定义                                            | 用途                                                    |
| ------------------ | ----------------------------------------------- | ------------------------------------------------------- |
| `recall-eval` must | 固定语料库 + clue → 期望 MemoryItem / 邻域约束  | CI 回归检索契约（≈ **51 must**）                        |
| `hybrid-eval` must | Hybrid 路径（mock embed）                       | 融合回归（≈ **8 must**）                                |
| §5.9 / TTE         | 真实库 + 真人确认；TTE-V / Success@180 / ECS 等 | **唯一**对外 Beta 质量门；**禁止**用路由或离线 NLU 代替 |

**模型对比时：** 固定库与 Filter/Hybrid 代码，只换 NLU 补全；报告须分列 **L2 槽位** 与 **L3 邻域命中**，不得合并成一个「准确率」。

#### C. `framing_nlg` / `follow_up_nlg`

| 成功                                             | 失败 / 可接受残差                                              |
| ------------------------------------------------ | -------------------------------------------------------------- |
| Zod 过；reply 可展示；chips 过切割力门禁（若挂） | Zod 失败或异常 → 规则 framing（**产品可接受**）                |
| 文案不声称唯一神谕；不改 `ParsedRecallClue`      | 合法但「空话」→ 体验差，属 L2 主观/量表，**不**进 must CI 默认 |

#### D. `narrow_polish`

| 成功                                                   | 失败                                 |
| ------------------------------------------------------ | ------------------------------------ |
| examples 与选定词 **同一 token identity**（fold 门禁） | 造词 / 不等长 → 丢弃润色，用规则举例 |

#### E. `enrichment`

| 成功                                                | 失败                                                 |
| --------------------------------------------------- | ---------------------------------------------------- |
| Worker 解析 proposal 非 null；扩展 merge 后字段合法 | 解析 null / 配额 → 规则-only；**不得**脏写未校验字段 |

#### F. `gs_samples`

| 成功                           | 失败                           |
| ------------------------------ | ------------------------------ |
| 4 条可展示口语 clue，可 Try it | 解析/配额失败 → 模板；不挡主找 |

#### G. Embedding

| 成功                                | 失败                                                                           |
| ----------------------------------- | ------------------------------------------------------------------------------ |
| 维数合法；Hybrid 可用；余弦排序稳定 | 失败降级关键词；**弱向量甩无关**由内容佐证门 / Hybrid 护栏管，非 chat 换模范围 |

### 2.3 核心优先序（RECOMMENDATION）

1. **先钉 NLU L1+L2**（parse-gold must 不退 + stretch 抬升可测）。
2. **同输入下**再看 L3（recall/hybrid must 或固定探针库），证明换模是否传导到邻域。
3. NLG / enrichment / GS：以 **降级率 + 门禁通过率 + 成本/延迟** 为主；主观文案抽样为辅。
4. §5.9 始终**另轨**；路由基线（方案 §5.3）只回答「要不要分档模型」，不回答「Beta 过了没」。

## 3. 离线评测方案

### 3.1 测试集分类

| 集                          | 层          | 样本来源                           | 标注                             | 自动化                  |
| --------------------------- | ----------- | ---------------------------------- | -------------------------------- | ----------------------- |
| **PG-must**                 | NLU L2      | 现有 `parse-gold-cases` must       | 槽位 expect（已有）              | Vitest / `runParseGold` |
| **PG-stretch**              | NLU L2      | 现有 stretch + 可增口语难例        | 同槽位规范                       | 汇报，不挡 CI           |
| **RE-must**                 | L3          | `recall-eval-cases`                | gold id / 邻域约束               | CI must                 |
| **HY-must**                 | L3 Hybrid   | `hybrid-eval-cases`                | 同上（mock embed）               | CI must                 |
| **NLU-live-shadow**（可选） | L1+延迟     | 匿名化生产 clue 快照（须隐私规范） | 仅 schema/超时，**不**标金标槽位 | 离线重放 completer      |
| **NLG-smoke**               | NLG L1+门禁 | 固定 Framing facts 快照            | chips 切割力 / fold              | 小集单测扩展            |
| **ENR-smoke**               | enrichment  | 固定标题/摘录 fixture              | proposal Zod + merge 快照        | Worker/扩展单测         |

**样本来源纪律：**

- 英语口语为主（产品 Recall 主路径）；**禁止**把中文线索当 P0 换模必测。
- **禁止**为过 case 加生产内容别名灰名单（ADR-005）。
- 真实库 TTE / Outcome **不进**本离线集冒充全量；可另做维护者本机金标卡（PII 不入库）。

### 3.2 标注规范（NLU）

与 `ParseGoldSlots` 对齐：

- 字段省略 = 不检查。
- `null` = 必须缺失。
- `contentTermsMustInclude` / `MustExclude` / `Exact`。
- `note` 写中文出题意图（开发者面）。
- 新增 case：先写 expect，再跑规则与候选模型；**禁止**「看模型输出再写 expect」导致过拟合（见 3.4）。

### 3.3 对比与回归流程

```text
固定：cases + nowMs（PARSE_GOLD_NOW_MS）+ prompt/schema 版本号（记录 git SHA）
  → Provider A（现网 Flash）与 Provider B（候选）同 messages
  → 各自：L1 解析成功？L2 judgeParseGold？
  → 汇总：must 通过率、stretch 抬升、失败 id 列表、P50/P95 延迟、$/1k 次（若有价）
  → 若做 L3：同一 Parsed 下游禁用；或「整链只换 NLU completer」冻结 Filter/Hybrid
  → 回归：合入前 PG-must + RE-must 绿；候选模型报告存 docs/audits 或评测笔记（非营销）
```

**统一评分：**

| 指标              | 计算                                                     |
| ----------------- | -------------------------------------------------------- |
| SchemaPass@k      | L1 通过 / 总调用                                         |
| SlotMatch@must    | PG-must 全过数 / must 总数                               |
| StretchLift       | stretch 中 LLM 过且规则不过的 id 数（已有 compare 思路） |
| FallbackRate      | 运行时 `rules_fallback` / 尝试 LLM（日志另轨）           |
| Latency P50/P95   | 仅 completer 墙钟                                        |
| GateFail→template | NLG 降级率                                               |

### 3.4 偏差与评分一致性

| 风险                    | 对策                                                                 |
| ----------------------- | -------------------------------------------------------------------- |
| 集过拟合现网 Flash      | stretch/难例与 must 分轨；候选赢 must 但输难例要写明                 |
| 标注人看了模型再标      | 双人盲标 expect；分歧第三人；锁定后再跑模型                          |
| 把检索失败算成 NLU 失败 | 报告强制分列 L2 / L3；L3 失败做归因（理解偏 / 候选漏 / 排序 / 未存） |
| 语料只覆盖作者库主题    | must 保持机制型（时间/类型/行为/附注），少专名；专名仅 fixture       |
| NLG 主观分不一致        | 默认客观门禁；主观仅 5 点李克特小样本，不写进分模硬门槛              |
| 泄漏测试到 prompt       | 离线对比脚本不改生产 prompt；禁止把 gold 例句粘进 system             |

### 3.5 本阶段明确不做

- 不上新评测基础设施（队列、在线 A/B 平台）。
- 不改生产 Prompt/模型。
- 可用现有 `compare-parse-gold` + 手工/脚本切 completer mock 做 **一次性** 对比实验。

## 4. 模型选型标准

### 4.1 比较维度

| 维度           | 主看任务              | 备注                                           |
| -------------- | --------------------- | ---------------------------------------------- |
| 质量 L2        | **nlu** 优先          | SlotMatch@must、StretchLift                    |
| 质量 L3        | nlu 传导              | 仅在 L2 持平/更好时看 must 邻域；**另计** §5.9 |
| Schema 可靠 L1 | 全 chat               | SchemaPass；结构化 JSON 稳定性                 |
| 延迟 P50/P95   | nlu ≫ NLG             | 对照 12s 预算；NLG 影响体感次之                |
| 失败率         | 全任务                | timeout / 429 / provider_error                 |
| 成本           | token × 单价 × 频率   | nlu 次数高；NLG 可接受略差模型若 L1 稳         |
| 降级可接受性   | NLG / enrichment / GS | 高 → 更可留 Flash 或更小模                     |

### 4.2 哪些值得换 / 哪些继续 Flash

| 任务                                | 默认（无数据前）     | 值得认真试候选的条件（触发表对齐）                                                               |
| ----------------------------------- | -------------------- | ------------------------------------------------------------------------------------------------ |
| **`nlu`**                           | **继续 Flash**       | T-NLU：fallback/provider_error **持续显著**差于 NLG 且伤体验；或离线 L2 显著落后于候选且 L3 不退 | 换 **quality** 档（`AI_HOSTED_MODEL_NLU`）    |
| **`framing_nlg` / `narrow_polish`** | **继续 Flash**       | T-LAT/T-COST：NLU P95 贴 12s 且 NLG 占比高、token 贵                                             | 换 **fast/便宜** NLG 档；须 L1+门禁不恶化     |
| **`follow_up_nlg`**                 | 保持插座；生产近未用 | 仅当独立接线且有基线后                                                                           | 同 NLG 档                                     |
| **`enrichment`**                    | **继续 Flash**       | T-ASYNC：队列积压/限流                                                                           | 独立优先级或 balanced；另案                   |
| **`gs_samples`**                    | **继续 Flash**       | 成本敏感且模板可接受                                                                             | fast；质量门槛最低                            |
| **Embedding**                       | **保持 bge-m3**      | 本阶段 **不进** chat 分模                                                                        | 换 embedding 模型 = 另 ADR/重建向量，非本阶段 |

### 4.3 已有事实 · 待测假设 · 推荐决策

#### FACT（已核实）

- 六 chat kind + embed；默认单模 Flash；Phase 0–1 路由插座与 maxTokens 已落地。
- NLU 12s → rules_fallback；NLG 失败模板降级。
- 解析与检索 eval 已分家（parse-gold vs recall/hybrid must）。
- 配额 Free 60/月·10/日，Pro 2000/月·120/日（hosted 主桶）。
- ADR-004/010 禁止多 Agent 会商与默认多跳理解。
- 生产 Framing 芯片走 `framing_nlg`；`follow_up_nlg` 未进 Hybrid 主链。

#### HYPOTHESIS（待测 · 无数字则不写入「已证明」）

- Flash 在 PG-must 上已接近规则 must 天花板，stretch 才是换模收益区。
- NLG 换小模对 L3 **无影响**（因不改约束），只影响体验与成本。
- NLU 换强模可能抬升 stretch，但若 contentTerms 过碎/过宽，L3 可能不升反降。
- 两周日志后 T-NLU/T-LAT/T-COST 可能**全部不触发** → 保持单模是合法结案。

#### RECOMMENDATION（确认前不改生产）

1. **现在不分模**；执行路由方案 §5.3 两周基线清单。
2. **并行**（仍不改生产）：用现网 Flash 打一版 PG-must/stretch **基线快照**存档；候选模型仅在离线脚本对比。
3. 唯一优先深化评测面：**NLU**；NLG 仅在成本/延迟触发后再做小烟测。
4. 分模证据门槛（建议写入拍板记录）：
   - 样本：hosted ok **nlu ≥200**（或窗口 ≥14 天且总数足够）；
   - 离线：候选 **SlotMatch@must ≥ 现网** 且 stretch 有可解释抬升；
   - 传导：RE-must（或固定探针）**不退**；
   - 运维：P95 与失败率不劣于触发表阈值；
   - **书面**区分「路由运营闭环」与「§5.9」。
5. 无触发 → 按方案模板写「观察期无触发，保持 deepseek-v4-flash 单模」。
