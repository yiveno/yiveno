## 3. `day-hike` vs `hike`：匹配差异与本实验选择

实现：`exclude-content-terms.ts` → `fieldHitsExcludeTerm`。

| 排除词                      | 命中字段例                                                         | 不命中例                                             | 机制                                    |
| --------------------------- | ------------------------------------------------------------------ | ---------------------------------------------------- | --------------------------------------- |
| **`day-hike`**              | `day-hike …`、`day hike checklist`（连字符短语 → 连续 token 对齐） | 仅有 `hiking tips`（无 `day`+`hike` 相邻）；`hikers` | 多段对齐，**不是**「任意含 hike」       |
| **`hike`**                  | `day-hike`、`day hike`、`hiking`（双向屈折）                       | `hikers`、`Ashike`                                   | 单词 token + 屈折；**比 day-hike 更宽** |
| **`packing` / `checklist`** | 正文/标题含对应边界 token                                          | 无该词的 lodging                                     | 与连字符无关                            |

对本库禁止条 `hikingYellowstoneExcerpt`（标题 _Yellowstone day hike checklist_；正文含 _Day hike packing checklist…_）：

- `day-hike` **命中**（`day`+`hike` 相邻）
- `hike` **亦命中**
- `packing` / `checklist` **亦命中**（任一即可滤掉该条）

### 本实验采用：`excludeContentTerms = ['day-hike', 'packing', 'checklist']`

**原因（用户意图，非模型偏好）：**

1. 排除跨度字面是 **「day-hike packing checklist」**，不是「any hike / hiking」。
2. `day-hike` 保留用户给出的活动修饰；比裸 `hike` 窄，避免把「仅 hiking、非 day-hike 清单」类条目在语义上扩成同级排除（本 corpus 虽无此类条，契约仍按意图收紧）。
3. `packing`+`checklist` 锚定「清单」实体，与正向 lodging 确认正交。
4. **明确拒绝**把生产 LLM 常用的 `hike` 替换进冻结槽——那是提供商输出，不是本实验金标。

（对照：parse-gold must 规则侧亦用 `day-hike`；此处引用仅为一致性说明，**金标权威仍是本节用户意图**。）

**机制边界（有条件批准补充 · Normative for this experiment）：**

- 本冻结集 = **依据用户字面意图制定的实验金标**；不得用生产 LLM 或规则 parse 结果替代或回填。
- 执行侧是 **`filterMatchesByExcludeContentTerms` 词项/屈折/连字符短语匹配**，**不等于**完整语义理解（不保证同义改写、隐含否定、跨语言等价）。

## 4. 三策略 · 同一冻结槽 · 同一硬过滤 · 无绕过

### 4.1 共用输入

每案、每策略：`goldParsed` 仅来自 case 字段；**禁止** `parseRecallClue` / LLM。

### 4.2 共用过滤（拟实现）

抽离离线 helper（仍调用生产纯函数，**不改**其实现）：

```text
matches_pre  →  filterMatchesByExcludeContentTerms(matches_pre, goldParsed.excludeContentTerms)
             →  matches_post + 诊断（§5）
```

| 策略         | 滤前有序列表来源                                                                                          | 硬过滤                                                         |
| ------------ | --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| **Keyword**  | 现有 `recallByKeywordWithParsedClue(..., { parsed: goldParsed })` 产出的邻域 matches                      | 见 §4.3                                                        |
| **Semantic** | 现有余弦邻域 + 时间硬筛 + 槽位软加后的 matches                                                            | **必须**经上述 helper（当前 runner **无** exclude → 补上）     |
| **Hybrid**   | 现有 `fuseKeywordAndSemanticPools` + soft 佐证后的 matches（仍 **不用** 生产 `fuseHybridMatches` 全路径） | **必须**经同一 helper（在 soft 佐证之后、collapse 取 id 之前） |

### 4.3 Keyword 双滤风险与裁定（有条件批准修订）

生产编排 `recallByKeywordWithParsedClue` 在佐证后**已**调用 `filterMatchesByExcludeContentTerms`。  
契约裁定：

1. Keyword **允许**出口再经**同一函数**一次，以保证三策略出口同构。
2. **诊断必须分计**（禁止把编排内已剔与出口新增加总成「双倍排除」）：
   - `orchestratorInternalExcludedCount`：相对「strip exclude 的 keyword 预跑」池，编排完整 parsed 已剔除的条数
   - `exitNewExcludedCount`：出口 filter 相对「编排输出」**新增**剔除条数（幂等时须为 **0**）
   - `excludedCount`：滤前→滤后总剔除 = 上两者之和（断言相等）
3. **先测幂等**：`filter(filter(M,T),T) ≡ filter(M,T)`；Keyword 出口对编排已滤池 `exitNewExcludedCount===0`。
4. **禁止**改生产编排；**禁止**无诊断的 silently 双计。
5. 验收：最终 `rankedIds` 不得含仍命中有效 exclude 的条目。

### 4.4 确认无绕过

| 路径                                            | 绕过？                          |
| ----------------------------------------------- | ------------------------------- |
| Semantic 只按余弦截断直接出 id                  | **实施后禁止**（必须过 helper） |
| Hybrid 只走 `fuseKeywordAndSemanticPools` 出 id | **实施后禁止**                  |
| Keyword 丢掉 `parsed.excludeContentTerms`       | **禁止**                        |
| 用 `contentTerms` 冒充排除（旧冻结）            | **禁止**（§2 已改槽）           |

