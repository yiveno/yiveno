# Yiveno 国内化与多市场准备审计（2026-10）

> **本报告 = 阶段 A（现状）+ 阶段 B（P0/P1/P2）。** 阶段 C 改码默认暂缓，须维护者逐项确认。  
> 标签约定：**FACT** = 仓库证据；**INFERENCE** = 合理推断；**建议** = 设计意见；**待验证** = 未跑真机/法律结论。

## 0. 本轮目标契约（已对齐 · 默认拍板）

实施本报告时采用计划默认契约（维护者未另行放宽则不变）：

| #   | 原则               | 本轮含义                                                                            |
| --- | ------------------ | ----------------------------------------------------------------------------------- |
| 1   | **主体 ≠ 市场**    | 杭州注册公司是主体/税务选项；产品主市场仍为海外美式英语                             |
| 2   | **准备 ≠ 上线**    | 摸清硬耦合与中文检索缺口；不做 zh UI / 国内支付 / 境内机房                          |
| 3   | **分层分算**       | UI i18n ≠ 检索多语言 ≠ 支付多 MoR ≠ 合规跨境                                        |
| 4   | **不抢 §5.9**      | 北美产品验证与 Recall 质量主线不变                                                  |
| 5   | **不改 Normative** | 现行 **American English only** 仍有效；正式支持中文 clue/zh UI 须先改权威文档再改码 |
| 6   | **不建生产灰名单** | 禁止中文 alias 表冒充通解；中文 eval 若建也仅测试夹具                               |

**后续已部分落地（2026-10-25 · 基础中文 UI）：** 扩展 `_locales/zh_CN` + Settings 语言切换 + 官网壳/卸载页 i18n；**仍不做**中文 Recall、国内支付、双区域。详见同日交付说明。

**原审计本轮不做：** 第二支付商、双区域部署、把中文 Recall 写成已上线能力。


## 2. 六大方向审计

### 2.1 国际化与本地化（i18n / l10n）

#### 已具备

| 能力               | 证据                                                                                                                                              |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 扩展文案与逻辑分离 | `t()` → `chrome.i18n.getMessage`（`extension/src/infrastructure/i18n/t.ts`）；`core` 注入 `TranslateFn`（`extension/src/core/i18n/translate.ts`） |
| Key 对称门禁       | `message-keys.ts` ↔ `_locales/en/messages.json`；`bun run i18n:check`                                                                             |
| 单 locale 资源     | 仅 `extension/public/_locales/en/`；`manifest.json` `default_locale: "en"`                                                                        |
| 产品面禁用词扫描   | Search 等（`product-surface-label-policy.ts`，纳入 i18n:check）                                                                                   |
| 官网薄 i18n 骨架   | `website/src/i18n/t.ts` + `en.ts`（注释「当前仅 en」）                                                                                            |

#### 硬编码 / 耦合

| 项                    | 证据                                                                                                                                                                                | 影响                                                |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| **政策禁止多 locale** | 产品文档 §市场语言；`project.mdc`；ADR-002「禁止新增 zh_CN」                                                                                                                        | 加中文 UI 前必须改 Normative，否则与 agent 规则冲突 |
| build 清非 en locale  | `extension/scripts/clean-dist.cjs` 删除 `dist/_locales` 下非 `en`                                                                                                                   | 即使手加 zh 资源也会被清掉（有意）                  |
| **无应用内语言选择**  | Settings 无 language 分区（`settings-sections.ts`）；依赖 `chrome.i18n.getUILanguage()`                                                                                             | 浏览器 UI 语言 ≠ 产品文案语言时仍只出 en messages   |
| 官网主体硬编码英文    | 多数 Astro/Vue 页内英文；仅卸载页等走 `t()`                                                                                                                                         | 官网加中文成本高于扩展                              |
| 日期 locale 混用      | `format-recall-saved-time.ts` / `detail-export.ts` 硬编码 `en-US`；`format-library-saved-at.ts` / `Detail.vue` 用 `getUILanguage()`；官网 `website/src/services/date.ts` 为 `en-US` | 与「仅 en 产品」一致；未来多 locale 时需统一策略    |

#### 判断

- **FACT：** 扩展 i18n **工程路径可用**（再加 locale 文件 + 去掉 clean-dist 限制 + 改 Normative），但**当前刻意收束为 en-only**。
- **建议：** 现在**不要**为国内化加 zh 翻译；保留「资源文件 + t()」即可。
- **无需处理：** 为「未来可能」预埋 locale 切换 UI 或 profile.locale 字段。

### 2.2 核心检索 · 多语言适配（最高优先级评估）

#### Keyword / 倒排

| 事实                   | 证据                                                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------------------------- |
| CJK 有机制，非玩具开关 | `keyword-filter.ts`：无空格段整段 term（≤16）+ **首尾 2-gram**；汉字单字可用；分隔含 `，、；`           |
| 索引侧更密的 ngram     | `extract-document-index-tokens.ts`：compact 上 **1-gram + 全串滑动 2-gram**（`CJK_NGRAM_CHAR_CAP=120`） |
| 查询 vs 索引不对称     | 查询仅首尾 2-gram → 长中文短语中间片段可能弱于索引侧（**INFERENCE**：质量风险，待专项测）               |
| 拉丁形态变体           | `latinInflectionVariants` 等面向拉丁语系，对中文无意义（FACT 范围）                                     |

#### 理解层（规则 + LLM）

| 事实                       | 证据                                                                                                                             |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **槽位词典仅英文 surface** | `parse-recall-clue-lexicon.ts`（time / objectType / behavior）；产品文档明确「不再为中文保留 alias」                             |
| 内容词可保留汉字块         | `parse-recall-clue.ts` `extractContentTerms`：`[\u3400-\u9fff]+` 整段保留                                                        |
| LLM prompt EN-centric      | `build-llm-parse-prompt.ts`：英文 timeLabel/objectTypes；`contentTerms` 要求 lowercase English tokens；多词实体拆 `["li","bai"]` |
| enrichment 英文 canonical  | `worker/.../memory-enrichment-proposal.ts`：「Use English canonical tokens…」                                                    |
| clue embedding 文本偏英    | `build-clue-embedding-text.ts` 主要拼英文锚词                                                                                    |
| Getting Started 禁中文样句 | `gs-clue-samples-proposal.ts`：「Never output Chinese clues」                                                                    |

#### Embedding / Hybrid

| 事实                | 证据                                                                                                            |
| ------------------- | --------------------------------------------------------------------------------------------------------------- |
| 生产模型多语        | `@cf/baai/bge-m3`（`worker/src/handlers/ai-embed.ts`）                                                          |
| **模型 ≠ 链路可靠** | enrichment / embedding 文本 / 佐证门仍 EN 词面（见下）                                                          |
| 内容佐证门字面交集  | 产品文档内容佐证门；英文 clue × 中文标题易 ∅（TTE 归档已记跨语言案，`docs/archive/research/tte-beta-2026-09/`） |

#### Eval

| 事实          | 证据                                                                                        |
| ------------- | ------------------------------------------------------------------------------------------- |
| must 全英语   | `recall-eval-cases.ts` / `parse-gold-cases.ts` / `omnibox-eval-cases.ts`                    |
| 唯一中文 clue | `hybrid-eval-cases.ts` → `stretch-mixed-language-semantic`，**gate: stretch**（非 CI must） |

#### 判断

- **FACT：** 关键词层对中文有通用 ngram/单字；**理解层与 Normative 按设计不做中文 Recall。**
- **INFERENCE：** 「昨天保存的文章」类口语 → 规则时间/类型槽位基本空，依赖字面 + Hybrid + LLM 运气。
- **待验证：** 真实中文库 + 中文 clue 的 TTE / TopK；**不得**仅凭 bge-m3 宣称生产级中文检索。
- **禁止路径：** 堆 `昨天→yesterday` 内容灰名单冒充通解（违反 project.mdc 全量用户能力规则）。正确路径是：产品文档明示闭集槽位多语言 surface，或通用机制 + 诚实残差。

### 2.3 数据模型与多市场

| 项                                      | 证据                                                       | 判断                                |
| --------------------------------------- | ---------------------------------------------------------- | ----------------------------------- |
| LocalProfile / UserSettings / SyncPrefs | 无 locale / currency / timezone 持久字段                   | **无需预埋**（符合「勿为空字段」）  |
| Supabase `profiles`                     | 迁移仅 id/name/email/avatar/bio/时间戳                     | 同上                                |
| 订阅/付款                               | `currency` 来自支付投影；缺省常落 `USD`（`projection.ts`） | 用户级市场字段与支付币种勿混为一谈  |
| 反馈可选 language/timezone              | 卸载页 `navigator.language` 上报，非用户设置               | 可观测性有钩子，非产品偏好          |
| 云同步类型                              | ADR-017 仅 `text_excerpt`；UTF-8 文本无编码限制（FACT）    | 中文内容本机/云存储**无**字符集障碍 |
| 用户 UI 语言 vs 内容语言                | 未建模区分                                                 | 未来需要时再加；现在不必            |

**结论：** 数据模型**没有**必须现在改的多市场阻塞；过早加 country/locale 字段会增加迁移噪音。

## 3. 能力对照小结

### 3.1 已具备（可演进的基础）

- 扩展 `t()` + en messages + CI `i18n:check`
- Keyword CJK ngram/单字通用机制
- Embedding 模型族多语（bge-m3）
- 云同步仅摘录、本机优先、删除/导出路径
- AI chat provider 可切换（运维面）
- Billing 事件幂等键含 `provider`（虽 CHECK 锁 dodo）

### 3.2 有意收束（不是疏漏）

- American English only（UI / clue / 测试语料 / GS 样句）
- clean-dist 删除非 en locale
- 规则 lexicon 无中文 surface
- 单一支付 MoR Dodo + USD 展示

### 3.3 未来高成本风险点（记录，多数不改）

1. Normative「禁止 zh」与「杭州主体 + 未来国内业务」叙事未建模 → agent 易误开或误拒
2. 中文检索无 must 护栏 → 静默以为「有 CJK ngram = 已支持」
3. Billing CHECK=`dodo` → 第二 MoR 需迁移
4. 官网硬编码英文面大 → 晚做翻译成本高但**可接受**（未验证国内官网需求）
5. 数据在美站 + 默认 DeepSeek → 跨境叙事需法务，非现在双机房

### 3.4 当前不需要处理

- 预埋 `profiles.locale` / `currency` / `country`
- 接微信/支付宝或人民币价
- 境内独立 Supabase / Worker
- 全量 zh UI 翻译
- 重写检索或换 embedding 模型
- 为日期格式做完整 ICU 框架（en-only 下 `en-US` 硬编码可接受）
