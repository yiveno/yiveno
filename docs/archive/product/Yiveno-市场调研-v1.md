## 0. 为什么现在暂停补做

近期已在 **英语规则 parser、enrichment、对话式 Recall UI** 上投入较多工程，但以下问题仍缺乏一手证据：

| 缺口                                      | 风险                                    |
| ----------------------------------------- | --------------------------------------- |
| 目标用户是否愿为「模糊线索找回」换习惯    | 做成「更好的书签搜索」，与 Google 硬碰  |
| 首发市场语言与区域                        | 日语 UI 用户得不到口语 Recall，体验断层 |
| 付费意愿与定价锚点                        | 功能堆叠但无人买单                      |
| 分发渠道是否可达                          | 产品好但无人知道                        |
| 与 Readwise / Raindrop 等的差异是否被感知 | 品类认知混乱                            |

**Normative 产品方向暂不变**；在本文 §8「继续开发前门槛」满足前，**优先验证假设，暂缓扩大 parser 语种 / LLM / 新功能面**。

## 1. 研究目标（要回答什么）

1. **市场有多大？** TAM → SAM → SOM（Chrome 扩展 · 个人知识捕获/找回）
2. **用户是谁？** 谁会 Capture、谁会 Recall、谁愿付费？
3. **竞争格局？** 用户今天用什么、切换成本在哪、Yiveno 的楔子是什么？
4. **语言与区域？** 英语是否应 P0；日语/韩语/西语何时投入？
5. **分发与商业化？** 从哪获客、愿付多少、Free/Pro 边界？

## 3. 市场规模（数量级）

### 3.1 TAM — 浏览器扩展大盘

| 指标             | 估算                        | 说明                   |
| ---------------- | --------------------------- | ---------------------- |
| 全球 Chrome 用户 | ~36–38 亿（2024–25 估）     | Google 未持续公开      |
| CWS 上架扩展     | ~11–18 万（不同统计口径）   | 85%+ 安装量极低        |
| 扩展大盘收入     | ~$35–42 亿/年（行业报告估） | 含 B2B、广告、订阅混合 |
| 生产力扩展品类   | 最大品类之一                | 与 Yiveno 品类相关     |

**解读：** 盘很大，但**长尾极长**——中位扩展仅数十用户；赢家集中在清晰痛点 + 分发。

### 3.2 SAM — 个人「捕获 + 日后找回」可服务市场

**操作定义：** 使用 Chrome、会主动保存网页片段/书签、有「过后想找回来」场景的知识工作者。

| 因子                             | 粗估                                           |
| -------------------------------- | ---------------------------------------------- |
| Chrome 用户中「会收藏/标注」比例 | 难量化；经验上远小于 100%                      |
| 扩展可触达（排除中国区 CWS 等）  | 全球 Chrome 用户大部分，但中文母语盘短期难触达 |
| 与 Yiveno 场景匹配               | 再缩一圈：愿装扩展、愿划词、库会增厚           |

**SAM 粗估（假设）：** 全球 **数千万～1 亿+** 潜在用户（数量级，非精确）。

### 3.3 SOM — Yiveno 前 12–24 个月可拿下的部分

| 情景 | 活跃用户数 | 假设                                          |
| ---- | ---------- | --------------------------------------------- |
| 悲观 | 1k–5k      | 无分发、Recall 命中率不够、留存差             |
| 基准 | 10k–50k    | 英语区 PH/社区冷启动 + 口语 Recall 有肉眼爽点 |
| 乐观 | 100k+      | 口碑 + 付费转化 + 某渠道爆款                  |

**当前无自有 CWS 数据，SOM 纯属假设；上线后应以周留存与 Recall 成功率为准。**

## 4. 语言与区域市场

### 4.1 三种「语言占比」口径（勿混谈）

| 口径                                | 英语约占比                | 对 Yiveno 的含义           |
| ----------------------------------- | ------------------------- | -------------------------- |
| 全球网民**母语**                    | **~26%**（2020 IWS）      | 英语不是人口大多数         |
| **网页内容**语言                    | **~49%**（Statista 2025） | 用户存的内容近半是英语     |
| **可触达 + 工作语言**（扩展付费盘） | **粗估 55–70%**           | 与分发、付费、技术用户重叠 |

### 4.2 主要语言/区域 Tier（与产品文档 §0.1.1 对齐）

| Tier   | 区域/语言                             | 网民或内容信号          | 扩展分发                   | 口语 Recall P0     | 建议                    |
| ------ | ------------------------------------- | ----------------------- | -------------------------- | ------------------ | ----------------------- |
| **T1** | 英语（美加英澳 + 印度等英语工作用户） | 内容 ~49%；付费意愿最高 | PH、HN、Reddit、X、SEO     | **完整 parser**    | **首发主攻**            |
| **T2** | 西欧（德法荷等）                      | 内容 5–6% 各            | CWS 国家数据驱动           | 英语 parser 常够用 | UI 本地化按需           |
| **T3** | 日语                                  | 网民 ~2.6%；内容 ~5.2%  | 本地社区、质量敏感         | 需 alias 或 LLM    | **P1+**，勿 P0 全量     |
| **T3** | 韩语                                  | 内容 ~0.8%              | 本地应用生态               | 同左               | P1+                     |
| **T4** | 简体中文                              | 网民 ~19%               | **CWS/防火墙：短期不可达** | 不优先             | 仅 dev 便利，不主导设计 |

### 4.3 区域付费信号（二手，待验证）

| 区域        | Chrome 份额（估） | 扩展付费意愿（行业博客） | 说明                |
| ----------- | ----------------- | ------------------------ | ------------------- |
| 北美        | 高                | 高（$5–15/月）           | AI 生产力扩展主战场 |
| 西欧        | 高                | 中（$3–10/月）           | 隐私/GDPR 叙事重要  |
| 印度        | 很高              | 很低                     | 用户多，ARPU 低     |
| 东亚        | 中                | 中–高（日本）            | 本地语言预期强      |
| 拉美/东南亚 | 中高              | 低–中                    | 增长快，付费弱      |

## 5. 用户画像（假设）

### 5.1 核心画像 A — 「会划的人」（Primary）

- **谁：** 开发者、产品/设计、研究员、重度信息消费者
- **行为：** 已用书签或高亮，但**不爱整理文件夹**
- **痛点 B（产品文档）：** 记得存过，不记得标题/路径/精确词
- **成功标准：** 模糊说一句 → 第一屏进入正确邻域（短名单含目标）；Top1 经常就是，但作建议而非神谕
- **愿付费若：** Recall 明显优于 Chrome 搜索 + 同步/语义（Pro）

### 5.2 画像 B — 「只收藏从不找」（Secondary，非首期）

- 书签 hoarder，很少 Recall → 库厚但 Yiveno 价值难体现
- **策略：** 不服务为首要人群；Capture 爽点可吸引，但留存靠 Recall

### 5.3 画像 C — 「几乎不 Capture」（排除）

- 产品文档 §0.1.1 已排除：库空则无 Recall 燃料

### 5.4 Jobs-to-be-done（JTBD）

| 场景      | 用户话                           | 现有替代                 | Yiveno 楔子                |
| --------- | -------------------------------- | ------------------------ | -------------------------- |
| 读过一半  | 「前段时间看了一半的那篇文章」   | 历史记录、Google、凭运气 | 行为 + 时间 + 类型线索     |
| 存过一句  | 「我划过那句关于 xxx 的话」      | 找不到高亮               | 摘录 + 个人痕迹            |
| 存过歌/站 | 「昨天循环很多遍的那首」         | 播放历史（跨站难）       | 打开次数 + enrichment      |
| 存过文档  | 「我附注过 deploy 很好的那个页」 | 书签附注难找回           | `clues.note` + 对话 Recall |

## 6. 竞争格局

### 6.1 直接/邻近竞品

| 产品                   | 定位            | 强项             | 弱项 / Yiveno 差异                  |
| ---------------------- | --------------- | ---------------- | ----------------------------------- |
| **Chrome 书签 + 搜索** | 默认、零成本    | 普及、同步       | 模糊线索、个人痕迹、口语 Recall     |
| **Google 搜索**        | 全网            | 覆盖一切公开页   | **找不到你的私有痕迹**（摘录/附注） |
| **Raindrop.io**        | 美观书签管理    | 视觉、集合、协作 | 偏整理；非「记忆口语」              |
| **Readwise Reader**    | 阅读 + 高亮复习 | 高亮工作流、导出 | 贵；复习系统；非「随意存随时找」    |
| **Memex / WorldBrain** | 全文索引、历史  | 本地、可搜全文   | 重；隐私敏感；非对话式记忆          |
| **MyMind**             | AI 收藏         | 视觉、自动标签   | 偏灵感库；助手感；定价              |
| **Notion Web Clipper** | 进笔记库        | 与笔记一体       | 创作/整理路径；非轻 Capture         |
| **Pocket**（已转型）   | 稍后读          | 品牌认知         | 品类信心动摇；非个人痕迹专精        |

### 6.2 竞争维度矩阵（假设）

| 维度                  | Chrome 书签 | Raindrop | Readwise        | Yiveno 目标      |
| --------------------- | ----------- | -------- | --------------- | ---------------- |
| Capture 负担          | 低          | 中       | 中              | **极低**         |
| 模糊 Recall           | 差          | 中       | 中（标签/搜索） | **高（核心）**   |
| 个人痕迹（摘录/附注） | 弱          | 弱       | **强**          | **强**           |
| 对话式澄清            | 无          | 无       | 无              | **有**           |
| 价格                  | 免费        | 订阅     | 订阅            | Freemium（待定） |

### 6.3 「为什么不用 Google」— 必须能讲清的句子

> Google 找得到**公开互联网**；Yiveno 找得到**你划过、附注过、反复打开过的那条**。

若用户库以**纯 URL 书签**为主且无摘录，Yiveno 优势会被削弱——与 §0.1.1「摘录主角」一致。

| 优先级 | 渠道                                       | 适合阶段                         | 说明                                         |
| ------ | ------------------------------------------ | -------------------------------- | -------------------------------------------- |
| P0     | Product Hunt / Hacker News                 | 冷启动                           | 英语区、重产品故事                           |
| P0     | Chrome Web Store SEO（关键词）             | 持续                             | bookmark recall, highlight save, read later… |

## 8. 商业化（假设，待验证）

### 8.1 品类付费参考（二手）

| 品类                  | 常见 Freemium 价带 |
| --------------------- | ------------------ |
| 生产力扩展            | $3–7/月            |
| 开发者工具            | $5–15/月           |
| 阅读/高亮（Readwise） | 更高 ARPU          |

### 8.2 Yiveno 建议分层（与产品文档 §A.3 / §5.1 对齐）

| 层级 | 包含                                                       | 目的         |
| ---- | ---------------------------------------------------------- | ------------ |
| Free | 本地 Capture、关键词 Filter、基础 Recall                   | 养库、养习惯 |
| Pro  | Hybrid/embedding、云同步、托管口语 LLM（月配额）、更高配额 | 变现         |

定价锚点（展示用，待 H4；结账以 Gumroad 为准）：**$5.99/月 · $59/年**。路线图 Power User / Team 预留不售。

**关键验证：** 用户是为 **Recall 命中率** 付费，还是为 **同步** 付费——决定 Pro 卖点排序（当前卖点主因 = Hybrid）。

## 9. 对当前产品方向的启示（基于 v1 研究）

### 9.1 与现有工程投入的对齐度

| 已做                     | 市场假设是否支持      | 说明                           |
| ------------------------ | --------------------- | ------------------------------ |
| 英语 parser + enrichment | ✅ 支持 T1 首发       | 方向正确，但需**真实语料验收** |
| 对话式 Recall UI         | ✅ 支持差异化叙事     | 需 Recall 命中率撑起体验       |
| 日语/多语口语 parser     | ⚠️ 无数据支持 P0 投入 | 等有 T3 用户信号再做           |
| 零锚点助手式 demo        | ❌ 与定位冲突         | 产品文档已禁                   |
| 书签树整理               | ❌ 市场不需要楔子     | 产品文档已禁                   |

### 9.2 建议的战略焦点（暂停后）

1. **单市场打穿：** 英语区知识工作者，不扩散语种功能
2. **单场景打穿：** 「记得存过 + 模糊线索」Recall，不做生活助手
3. **单资产打穿：** 摘录 + `clues.note` 主角，书签配角
4. **单分发验证：** 1–2 个渠道可复现安装，再扩功能

### 9.3 语言策略结论（研究版）

- **不是**「全球每种语言都做一套映射再上线」
- **是**「T1 英语体验达标 → 用 CWS 国家/语言数据决定 T2/T3」
- 日语用户：**可安装 + 可 UI 日语**，但口语 Recall 降级需**对外诚实**或 **P1 补高频 alias**

## 11. 继续开发前门槛（建议）

在恢复「扩大 parser / 新功能 / 多语言」之前，建议至少完成：

- [ ] **H1** 完成 5 场英语区用户访谈（提纲见 §12）
- [ ] **H3** 建立 20+ 条真实英语 Recall 语料 benchmark（含通过/失败标准）
- [ ] CWS 上架或等价可安装包，能看 **安装 → 首次 Capture → 首次成功 Recall** 漏斗
- [ ] 竞品速览表更新（各 30min 深度试用，记录 Recall 路径）
- [ ] 本文 v1 评审：团队对 **T1 英语首发** 书面确认

**未过门槛前：** 可修 bug、可做 benchmark 所需的小改动；**不扩**日语 parser、不上 LLM 主路径、不加新品类功能。
