## 0. 一句话目标

把现行实现收束到不可动摇的主题：**Yiveno = 那个找东西的**——自然语言稳定对上用户自己的内容；不助理化、不同步中台化、不过早平台化。

---

## 1. 会话共识 vs 现行差异

| 主题     | 现行（改版前）                           | 共识目标                               | 差距性质               |
| -------- | ---------------------------------------- | -------------------------------------- | ---------------------- |
| 对外印象 | 「记忆硬盘」叙事完整，锋利品类标签偏软   | 用户只记住「那个找东西的」             | 文案 / 功能筛题        |
| 命题验收 | 有 eval 门禁，但易被「先上线看市场」稀释 | NL↔内容关系**先验**验死                | 流程纪律               |
| 能力承诺 | A.1.1 有 40–75% 判断，档位不够硬         | A 必达 / B 追问内 / C 不承诺           | 文档已补 Normative     |
| 空结果   | 诚实 no_match；话术边界未钉死            | 导向 Capture/追问；**禁偏好建档闲聊**  | 文案 + NLG/模板        |
| 冷启动   | 承认开头最难                             | 库谷底正常；**第一天体验仍须设计到位** | 体验路径               |
| 语料扩展 | 摘录+书签；Notion 多作竞品禁区           | **适配器可插拔**；导入 ≠ 做 Notion     | 架构契约缺文档化       |
| 框架远景 | 几乎未写                                 | 个性化检索框架 = 远景；当前不做平台    | 已写入附录 A.7         |
| AI 架构  | 约束型检索已在 Normative                 | 与业界成熟形态同构；继续守门禁         | 主要是守，不是另起炉灶 |

**结论：** 主链（LLM 理解 → 门禁 → Filter/Hybrid → 真实 id）方向正确；改版重点是**收题、先验验收、空结果契约、适配器形状**，不是重做一套 AI。

## 2. 明确不做（本计划全程）

- 个人助理 / 偏好人格记忆 / 零锚点「替你决定」
- 同步中台、连接器 Logo 墙、未过门槛的 Notion/Docs 大导入
- 开放框架 API、多租户检索平台
- 独立笔记创作主路径、书签智能整理
- 用更强模型叙事替代找回命题验收

## 3. 波次计划（对齐产品文档 §8 R0–R∞）

### R0 · 命题先验（先做）

**状态：** 进行中 → **核心交付已落地（2026-08-11）**；退出标准见下。

**目标：** 证明「口语能对上内容（或诚实没有）」——现在就能验，不等市场。

| 交付                                                                         | 验收                       | 落地                                              |
| ---------------------------------------------------------------------------- | -------------------------- | ------------------------------------------------- |
| 收束 / 补齐 `recall-eval` **must**（有锚点命中、无数据诚实空、禁无 id 答案） | CI / 本地 `must` 全绿      | ✓ 修 Type B 时钟；增 `r0-zero-anchor-*`；空库单测 |
| 对照 §0.1.1 档位 A/B：至少覆盖「可区分线索命中」与「过糊 → 追问」            | 用例表进仓库或 §5 手工步骤 | ✓ case note 标 R0/A·B；覆盖检测单测               |
| 审计空结果 / 追问文案：无助理人设、无「告诉我喜欢什么我记住」主路径          | 文案清单 + i18n key 复查   | ✓ i18n 收束；LLM prompt + 门禁拒收偏好建档/假命中 |

**退出标准：** 团队能回答「命题是否成立」而不依赖 DAU。→ **eval must 即命题尺子；本地相关单测已绿。**

**本波关键路径：**

- `frontend/src/core/recall/eval/*`
- `frontend/src/core/recall/understand/build-llm-follow-up-prompt.ts`
- `frontend/src/core/recall/understand/map-llm-follow-up-proposal.ts`
- `frontend/public/_locales/{en,zh_CN}/messages.json`（空结果 / miss 追问）

**下一步：** 进入 **R1**（冷启动闭环手工脚本 + Popup 空态审题）。→ **R1 已落地，见下节。**

### R1 · 冷启动不破题

**状态：** **核心交付已落地（2026-08-11）**；真机 §5.8 须发版/改到时手跑。

**目标：** 第一天不是破产品；空库失败是诚实，不是冷漠或乱猜。

| 交付                                            | 验收                                | 落地                                               |
| ----------------------------------------------- | ----------------------------------- | -------------------------------------------------- |
| 空结果话术对齐契约（痕迹不足 → Capture / 追问） | 手工脚本：空库口语 → 预期文案与 CTA | ✓ §5.8 A；空库 idle 改「先留下一点痕迹」           |
| 最短成功闭环：导入或划存 → 用自己的话找回一次   | §5 可复现步骤                       | ✓ §5.8 B                                           |
| Popup/空状态不暗示「全能助理」或「啥都做」      | UI 文案审题                         | ✓ 欢迎/空态/miss 收束；`popup-empty-copy` 禁词矩阵 |

**退出标准：** 新用户 10 分钟内能完成一次「存 → 找」正向闭环，或明确知道下一步该存什么。→ **文案与脚本已齐；真机按 §5.8 勾选。**

**下一步：** 进入 **R2**（语料适配器契约文档化 + 差距清单）。→ **R2 已落地，见下节。**

### R2 · 语料适配器契约

**状态：** **核心交付已落地（2026-08-11）**；连接器实现不在本波。

**目标：** 插头形状稳定；摘录/书签是参考实现；为未来第三方导入留位但不提前堆砌。

| 交付                                                                   | 验收                          | 落地                                                                  |
| ---------------------------------------------------------------------- | ----------------------------- | --------------------------------------------------------------------- |
| 文档化 Corpus Adapter 边界：认证 / 拉取 / → MemoryItem 映射 / 质量门禁 | 工程备注或 `core/memory` 旁挂 | ✓ `docs/engineering/语料适配器契约.md` + `corpus-adapter-contract.ts` |
| 梳理现有 bookmark import / excerpt capture 与统一契约的差距清单        | 差距表；非阻塞项进 backlog    | ✓ 差距 G1–G7（弱锚点门禁 G3、bulk enrichment G4 等）                  |
| 第三方源准入规则（正文/出处/id/可问字段最低标准）                      | 实现侧 checklist              | ✓ 10 项 + `THIRD_PARTY_CORPUS_ADMISSION_CHECKS`                       |

**退出标准：** 新语料源「能不能接」有客观门槛；接了不会绕过检索主链。→ **门槛已成文；无第三方连接器擅自开工。**

**下一步：** **R3** 按找回增益推进倒排等；外部源仅在过准入清单后单点试点。→ **R3 弱锚点 + 倒排 Phase 1 已落地，见下节。**

## 4. 建议执行顺序（近 2～4 周）

```text
R0 文案与 must eval 收束
  → R1 空结果 / 冷启动闭环
    → R2 适配器契约文档化 + 差距清单
      →（并行）倒排等 B 阶段余项按找回增益插入
        → 外部导入仅在 R2 退出后单点试点
```

默认**先文档与验收，再大功能**；当前 WIP（Recall follow-up / enrich 等）合入时须不违反空结果契约与反助理 MUST NOT。

---

## 5. 与代码改动的衔接原则

1. 改架构 / 消息 / UI 硬约束 → **先改产品文档**。
2. Recall / Capture 用户可感变更 → **先有 must 或 §5 步骤**。
3. 新增「导入某某」→ 先过 R2 准入，再写连接器。
4. NLG / 追问 → 只服务找东西；空结果不开放偏好建档。
