# Yiveno Strategic Analysis Framework

**研究参考日：2026-08-23（GMT+8）**。本文件把已收集的产品事实转化为可审计的战略判断。所有产品能力事实须回链至 `evidence_log.md`；坐标、评分与优先级是分析师推断，不是厂商自报数据。

## 1. 市场边界

> **Yiveno 所在的实际市场是“以用户主动保存的互联网内容为起点的个人信息召回（personal information retrieval）”，并向个人上下文/Agent retrieval layer 演化。**

这一市场不等于传统 Bookmark Manager，也不等于企业知识管理软件。其工作对象是用户能授权收集、长期拥有并再次使用的网页、社交收藏、文章、视频、PDF、代码资源和相关元数据；关键价值是降低“我知道我见过它，但找不回来”的检索成本。

| 层级                   | 代表产品                                                                 | 主任务                               | 主要付费理由                      | Yiveno 的相对位置                                 |
| ---------------------- | ------------------------------------------------------------------------ | ------------------------------------ | --------------------------------- | ------------------------------------------------- |
| L1：书签卫生           | Chrome Bookmarks、Trove Chrome、Anybox                                   | 存、分、去重、备份                   | 效率、可控、隐私                  | 必须兼容，不能停在此处                            |
| L2：阅读与归档         | Raindrop、Readwise Reader、Recall                                        | 保存正文、阅读、标注、归档           | 不丢内容、复习、写作复用          | 是近期最直接的替代集合                            |
| L3：无感个人知识       | mymind、Recall、Capacities、Fabric                                       | 自动提取、关联、联想召回             | 降低组织负担与心智负担            | 必须在检索正确性上胜出                            |
| L4：个人上下文 / Agent | Mem、Fabric、Trove（usetrove）、Lowside Trove、ChatGPT/Claude/Notion MCP | 把个人资料作为 AI 的可授权上下文     | 不重复 briefing、提高 AI 工作质量 | 长期平台方向，而非 MVP 类别                       |
| L5：浏览器原生记忆     | Chrome、Dia、Comet、Gemini                                               | 用历史/标签页/连接应用辅助搜索或行动 | 零摩擦、默认入口                  | 最大分发与捆绑威胁；也是获取数据的潜在合作/依赖层 |

## 4. 战略选择评分模型

每个候选定位按 1–5 分评分。综合分 = 20% 用户痛点 + 15% 愿付费 + 15% 差异化 + 15% 分发可行性 + 15% 技术可行性 + 10% 数据/学习壁垒 + 10% 风险倒扣（风险低分更高）。此模型用于相对优先级，而非对项目成功概率的精确预测。

| 定位                                    | 痛点 | 愿付费 | 差异化 | 分发 | 技术 | 数据壁垒 | 风险 | 加权总分 /5 |
| --------------------------------------- | ---: | -----: | -----: | ---: | ---: | -------: | ---: | ----------: |
| A. AI Bookmark Manager                  |  3.3 |    2.6 |    1.8 |  4.0 |  4.3 |      1.5 |  3.0 |        3.03 |
| B. Personal Knowledge Retrieval         |  4.4 |    3.7 |    3.8 |  3.8 |  3.7 |      3.4 |  3.4 |        3.76 |
| C. Personal Internet Memory             |  4.2 |    3.4 |    3.7 |  3.2 |  3.3 |      3.7 |  2.9 |        3.47 |
| D. AI Memory Layer for Individuals      |  3.9 |    3.5 |    3.5 |  2.6 |  2.7 |      4.1 |  2.4 |        3.20 |
| E. Personal Context Layer for AI Agents |  4.0 |    3.7 |    4.1 |  2.4 |  2.4 |      4.3 |  2.0 |        3.19 |

**判定：**B 是当前公司/产品认知定位，C 是 12–24 月品牌叙事，E 是在可靠检索、数据治理和用户授权基础上逐步打开的平台选项；A 是可发现性入口而非公司定位，D 不宜先于 B/C。

## 5. 技术壁垒判断

| 能力                                            | 复制难度 | 是否需长期用户数据 | 对 Yiveno 的优先级 | 判断                                                            |
| ----------------------------------------------- | -------- | ------------------ | ------------------ | --------------------------------------------------------------- |
| 单次 LLM 摘要 / auto-tag                        | 低       | 否                 | 低                 | 能改善 capture，不构成差异化。                                  |
| Embedding / 向量数据库                          | 低–中    | 否                 | 中                 | 是检索底座，不是 moat。                                         |
| Hybrid Search（keyword + full-text + semantic） | 中       | 部分               | 极高               | 决定 recall precision、延迟、解释性和用户信任。                 |
| 内容提取 / 元数据丰富                           | 中       | 部分               | 高                 | 直接决定资料可检索性与解析失败率。                              |
| Personal Information Graph                      | 中–高    | 是                 | 高                 | 只有在来源、实体、项目、时间和显性纠正持续积累后才有价值。      |
| Temporal / behavioral ranking                   | 高       | 是                 | 极高               | “几个月前”“当时在研究 X”“我曾经打开/高亮过”是难复制的召回信号。 |
| 多模态检索（视频/截图/视觉）                    | 中–高    | 部分               | 中                 | 适合后续高价值用户群，必须有清晰来源与成本控制。                |
| 可移植、最小授权的 MCP/API                      | 中       | 否                 | 高                 | 抵御单模型锁定；需要严格 scope、审计和用户可见来源。            |
| 自主 Agent / 自动执行                           | 中–高    | 是                 | 低（现阶段）       | 高风险且浏览器/AI 平台已有分发优势；早期不应做。                |
