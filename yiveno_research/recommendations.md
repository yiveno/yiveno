# Yiveno：差异化定位与产品取舍建议

**Yiveno 术语：** 见 [`docs/product/Yiveno-术语表.md`](../docs/product/Yiveno-术语表.md)（用户输入 = **clue**）。

**判断性质：**本文件中的产品能力事实来自 `evidence_log.md` 的一手来源；所有“应当”“不应当”“优先级”均为基于这些证据的战略推断。时间点为 2026-08-23。

## 一、明确定位：现在卖“可靠找回”，将来成为“可授权的个人互联网上下文层”

Yiveno 当前不应被定义为 AI Bookmark Manager、又一个 PKM、个人 second brain 或会自己做事的 Agent。更清晰且可检验的主张是：

> **Yiveno 是面向高频网络研究者的 Personal Knowledge Retrieval：把用户主动保存的互联网资料变成可验证、可再次找到、可安全交给任意 AI 的个人检索库。**

这一表述刻意把“主动保存的互联网资料”置于数据边界中心。它避开了对浏览器历史、邮箱、日历和即时通信数据的全量采集承诺，也避免与 Notion/Fabric 的全工作区、与 ChatGPT/Claude 的聊天记忆、以及与 Dia/Comet 的浏览器内行动入口正面对齐。它的价值不是把一切都收进来，而是让用户**在有价值的网络资料上拥有可靠的回忆、证据和控制权**。

| 层次               | 对外叙事                                                                                                              | 应在什么条件下进入                                                         |
| ------------------ | --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 当前（0–12 个月）  | **Personal Knowledge Retrieval**：保存过的互联网资料，任何线索都能找回，并返回来源与原文位置。                        | 先实现高质量 capture、完整 content archive、混合检索、证据回链和可靠同步。 |
| 邻近（12–24 个月） | **Personal Internet Memory**：记住资料的内容、来源、时间、关联项目和用户与其互动方式。                                | 证明 30/90 日召回、重复访问、跨来源检索和用户对“为什么推荐”解释的信任。    |
| 平台（24+ 个月）   | **User-authorized Context Layer for AI**：以最小权限向 ChatGPT、Claude、Cursor 等提供可撤销、可审计的用户资料上下文。 | 先完成可导出数据模型、来源级引用、scope/consent、审计记录、稳定 MCP/API。  |

## 二、优先客群与可证伪的需求假设

首发不应试图服务“所有想整理书签的人”。建议从**英语为主的跨平台网络研究型个人用户**切入：独立研究者、创作者、产品经理/设计师、开发者、研究生与重度知识工作者。他们的共同点不是职业标签，而是每周持续保存多种来源、会在数周或数月后找回、且对来源准确性有要求。

| 首发分群                | 高价值 Job-to-be-Done                                                     | 现状的替代组合                                 | 必须验证的付费触发                                | 不应作为首发承诺                                   |
| ----------------------- | ------------------------------------------------------------------------- | ---------------------------------------------- | ------------------------------------------------- | -------------------------------------------------- |
| 跨来源研究者            | “我记得看过/存过一段资料；给我找出来，并说明为什么是它。”                 | 浏览器书签 + Raindrop/Reader + 搜索 + 手动笔记 | 找回正确来源的时间节省、可引用原文、少切换工具    | 自动代写完整研究、全企业知识搜索                   |
| 内容创作者 / 设计研究者 | “按主题、视觉线索、时间与我过去的收藏，把可复用灵感找出。”                | mymind + Pinterest/Instagram saves + 文件夹    | 跨来源素材的再利用、项目 moodboard/brief 准备     | 成为视觉设计编辑器或社交网络                       |
| 开发者 / 产品人员       | “把 GitHub/X/文章/文档中已保存的证据，按问题交给 Claude/Cursor/ChatGPT。” | Lowside Trove + Obsidian + Readwise + LLM 聊天 | 可审计的 context pack 与可靠引用，不重复 briefing | 默认读取 cookie、批量全账号抓取、代替 IDE/文档系统 |

每个群体都应做 10–15 个 problem interview 和 2 周 diary study。合格信号不是“喜欢 AI”，而是以下任一行为被重复观察到：用户会在 60 秒内完成首次跨来源保存；在第 14 天至少主动检索 3 次；至少一次检索结果被用于写作、决策或给 AI 作为证据；用户愿意把旧收藏导入并选择持续同步。

## 三、MVP：以“可信召回闭环”而非“功能清单”取胜

### MVP 应包含的完整闭环

| 环节     | 必须实现的能力                                                                                                                            | 用户可见质量门槛                                                                   | 竞争逻辑                                                                                   |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Capture  | 浏览器 extension 一键保存；Share Sheet / paste URL；至少支持 article、PDF、YouTube、X/LinkedIn 保存链接；导入 Chrome/Raindrop/Pocket 文件 | 保存后即时给出状态；失败明确；原 URL、标题、作者、时间和来源恒久保留               | Raindrop、Reader、Recall 已把“保存”做成熟，Yiveno 只能在低摩擦与资料可恢复性上达标。       |
| Preserve | 阅读视图正文/清洗 HTML、原始链接、关键元数据、抓取时间、内容 hash、失败状态；可选本地加密缓存                                             | 用户看到的是“我保存当时的证据”，而非日后变化的网页幻影                             | Pocket 退出和 Raindrop 用户反馈说明可迁移、离线/归档和可靠性不是次要能力。                 |
| Retrieve | keyword + full-text + semantic 的混合检索，支持来源、时间、内容类型、收藏/打开/高亮等过滤；自然语言 **clue** 先返回候选卡片和证据片段     | 对“我几个月前在 X 看到的那篇讲……的文章”给出可判断的前 5 个候选，而非一段无来源回答 | Chrome 也能做单浏览器 history AI search；Yiveno 的胜点是跨来源、用户保存意图与可解释证据。 |
| Explain  | 每个结果必须显示：原始来源、保存时间、为何命中（关键词、段落、实体、相似内容、互动信号）、原文深链                                        | 用户可在 1 次点击内验证；无法确定时显示不确定性                                    | “引用来源”是平台型 AI 与成熟工具都在强化的信任规范。                                       |
| Reuse    | 一键导出 selected evidence pack：链接、摘录、引用、元数据；Markdown/JSON 导出；只读 MCP beta 或 copy-to-chat                              | Agent 获得最小必要上下文，且每条材料都有 source reference                          | 不从“代替 AI 聊天”入手，而从“让所有模型用到正确资料”入手。                                 |

### 明确不做（至少延后）

| 能力                                    | 不做的原因                                                                           | 何时重新评估                                                                          |
| --------------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| 自主 Agent 代办、自动下单/发信/修改网页 | 高权限、错误成本与浏览器平台竞争极强；Comet、Dia、Mem 已占据 “上下文→行动”叙事。     | 建立 scope、审计、撤销机制后，且用户已信任 retrieval accuracy。                       |
| 通用笔记编辑器、项目管理、多人协同套件  | Notion、Fabric、Obsidian 优势极深；会将小团队拖入无限 feature surface。              | 仅考虑“把 Yiveno 资料写入用户已有工具”的深集成。                                      |
| 图谱可视化优先                          | 图谱是一种解释/探索界面，不是首要 Job。Recall、Capacities 已证明其易被商品化为展示。 | 当实体/关系数据对召回确有提升、且用户可基于图谱完成任务时。                           |
| 默认抓取浏览历史 / 邮箱 / 日历 / 私信   | 与 Chrome、Gemini、Dia、Comet 的入口优势硬碰硬，并迅速抬高 privacy、安全和授权负担。 | 用户从保存资料库已获得可观价值，且逐源 opt-in 的价值被验证。                          |
| 首发自训练模型 / “自研大模型记忆”       | 资金消耗高且不构成现阶段产品差异。                                                   | 在有大量用户纠正/检索日志并具备隐私合规基础后，做轻量 reranking 或 personal ranking。 |

## 四、数据架构：把“资料”而不是“聊天摘要”作为一等公民

Yiveno 的长期壁垒不会是 embedding 或一个 LLM 摘要；这些都可替换。真正需要从第一天正确设计的，是可验证的资料对象、可解释的召回和用户可控的数据权利。

| 数据层                 | 关键对象                                                                                                      | 建议的设计选择                                                         | 为什么是壁垒                                                       |
| ---------------------- | ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------ |
| Source Ledger          | `Source`、canonical URL、origin platform、capture time、content hash、raw/clean version、parse status、rights | 不覆盖原链接；保存原始和清洗版本的关联；抓取失败可见；版本化           | 可证明资料来源与抓取时态，是高信任 recall 的最小资产。             |
| User Intent & Evidence | `SaveEvent`、collection、note、highlight、open/revisit、explicit relevance feedback                           | 绝不把隐式行为伪装为事实；用户可关闭行为特征；明确记录数据用途         | “用户为何保存、后来是否复用”比网页正文更有 personal ranking 价值。 |
| Entity / Project Layer | person、company、topic、project、claim、source relation                                                       | 人工纠正优先，LLM 提取只作为候选；记录置信度和来源                     | 长期形成跨来源的用户语义，而非单条文档向量。                       |
| Index Layer            | metadata index、full-text index、embedding index、freshness/interaction ranker                                | hybrid retrieval 先生成候选，再 rerank；每次检索保留 score rationale   | 降低向量幻觉，兼顾精确匹配、语义匹配和时间/行为信号。              |
| Access & Portability   | source-level scopes、read-only vs write、expiry、audit log、delete/export queue                               | MCP 默认只读和最小集合；任意连接器可撤销；Markdown/JSON/原始元数据导出 | 成为跨模型上下文层的信任基础，并把“可迁移”从承诺变成可操作能力。   |

## 五、商业化：卖“更快、更可信的再利用”，不是卖 AI token

建议采用 freemium + 个人订阅，且将价格与“检索/归档/再利用”而非摘要次数绑定。市场已有锚点从 Anybox 年付 $14.99 到 Raindrop 年付 $29、mymind 年付 $79–129 和 Readwise 年付 $119.88；它们对应从简单保存到高频阅读再利用的不同价值深度。Yiveno 初期不宜使用昂贵的 agent 定价，也不宜以极低 lifetime price 锁死持续存储、解析与检索成本。

| 方案         |                  建议价格 | 包含价值                                                                                  | 目的                                                       |
| ------------ | ------------------------: | ----------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Free         |                        $0 | 1 个浏览器、有限保存/全文索引、基础导入、非生成式检索                                     | 验证 capture→retrieve 激活；不让总结额度阻断核心体验。     |
| Pro          |     $6–8/月，或 $60–72/年 | 无限保存（合理使用）、完整 archive、跨来源连接器、hybrid recall、导出、基础 MCP read-only | 与 mymind/Reader 之间保留明显价格/价值区间；验证个人付费。 |
| Researcher   | $12–15/月，或 $120–150/年 | 多模态处理、更高同步频率、项目空间、证据包、advanced connector、API/MCP 配额              | 只在重度用户出现真实节省/复用时推出。                      |
| Team（后置） |                    按席位 | 共享资料库、权限、共享上下文策略、审计                                                    | 不是 MVP；不能在个人产品未验证前反向产品化。               |

模型成本可通过摘要/多模态的按需处理、可见队列和用户主动触发控制；每次查询都必须有明确 source attribution。不要把 BYO API key 设为唯一默认路径：它降低公司成本，却会把典型个人用户的激活摩擦推高；可将其作为 Pro 的隐私/高级选项。

## 六、90 天验证计划与成功/停止阈值

| 时间     | 目标                            | 关键实验                                                                              | 通过阈值                                                                          | 失败后的动作                                                                                |
| -------- | ------------------------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 0–30 天  | 验证 capture 的低摩擦和首次召回 | 扩展 + URL 保存 + 导入；对 20 名种子用户做可观察任务测试                              | ≥70% 在首次会话独立完成 5 次保存；≥60% 在 7 天内至少做 1 次检索                   | 若 capture 不通过，停止 AI 功能开发，重做入口/导入/状态反馈。                               |
| 31–60 天 | 验证检索是否真实优于已有工具    | 对每名用户收集 5 个“我以前见过”的真实任务；比较 browser history、现有书签工具、Yiveno | Yiveno 在 ≥60% 任务中给出用户认定正确的 top-3；中位找回时间低于现有方式 50%       | 若效果不达标，优先改 parser、full-text、metadata、query rewrite 和 reranker，不加 Agent。   |
| 61–90 天 | 验证重复使用与付费              | 证据包 / 导出 / read-only MCP beta；价格页+支付意向实验（不强制真实收费）             | 周活种子用户中 ≥35% 每周主动检索≥2 次；≥15% 对目标 Pro 价格给出明确付费意向或预付 | 若检索高但付费弱，细分为 Reader/Creator/Developer，重做 value metric，不扩大 data sources。 |

## 七、北极星与防呆指标

北极星不应是“保存数”或“AI 消息数”。建议采用：

> **Verified Retrievals per Weekly Active User（每周活跃用户经原文/来源打开确认的成功找回次数）。**

同时监控 `capture_success_rate`、`parse_complete_rate`、`top-3 judged-success rate`、`time-to-evidence`、`revisit-after-30/90-days`、`export/MCP use rate`、`source deletion SLA`、`consent revocation success`。只要 `verified retrieval` 没有持续改善，任何“memory”或“agent”叙事都应暂停扩张。

## 八、最重要的风险与反制

| 风险                               | 证据基础                                                                         | 反制                                                                                                        |
| ---------------------------------- | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 浏览器原生 AI 吞噬单浏览器历史搜索 | Chrome 已提供本地 AI History Search；Dia/Comet 将 tabs/history/连接工作流带入 AI | 不争夺单浏览器历史；做跨来源、保存意图、归档、关系和 model-neutral access。                                 |
| 大型 AI 平台成为用户默认记忆层     | ChatGPT、Claude、Gemini 均在推进跨聊天/应用的个人记忆与连接器                    | 做可导出、可解释、带资料级引用的独立 source layer；接入而非反对 MCP。                                       |
| 成熟 PKM/阅读器把基本功能商品化    | Raindrop、Reader、Recall、mymind 已具有 archive、全文、AI、跨端或知识图谱能力    | 用可量化的 retrieval correctness 做选择；不复制全套 editor/graph/agent。                                    |
| 个人资料的隐私、版权与平台政策风险 | Web 内容抓取、cookie 导入、社交 API/页面策略易变；用户也可能保存敏感资料         | 仅用户授权 capture；明确数据范围/删除/导出；不默认读取 cookie；source policy 分级；记录 parser 权限与失败。 |
| 存储/解析/LLM 成本失控             | 完整归档、多模态、同步和 Agent 会使边际成本不可预测                              | 原文解析和 embedding 先行，生成式任务按需；使用预算和回收策略；高成本媒体转入 Researcher。                  |

## 九、一句话决策

**做一个“能证明自己找对了”的个人互联网资料召回层；先让用户找到，再让 AI 使用；不要先让 AI 替用户行动。**
